## 1. 玩家体验与产品目标

```text
带着月亮或独自进入 Earth
    → 发现一个可见太阳 → 靠近时体会光照逐渐变化
    → 看到“E 回应光芒” → 按 E
    → Earth 大气与太阳光晕出现一次柔和响应
    → 响应结束，恢复当下距离对应的正常光照 → 继续探索
```

V1 表达“与一个事物同行”，V2 表达“被另一个事物影响，并作出回应”。太阳不被招募，不绕 Earth 同行，不增加伙伴数量。玩家无需先邀请月亮，也无需等待太阳随机说话才能主动互动。

V2 的成功标准是：玩家能区分“接近太阳的持续受光”和“主动按 E 后的一次回应”，且能在离开后继续正常探索。它不是能量收集、伤害、温度生存、任务解锁或天文模拟。

## 3. 本次包含与排除

### 包含

- 一个可辨认、离线程序生成的太阳模型，必要时加一层轻量光晕。
- 与太阳位置一致的主光方向，以及有上下限的接近增强效果。
- 使用既有 E 提示的一次主动光响应，含重复输入保护和短冷却。
- 太阳的原创短句注册到 `world.talkers`，沿用共享相遇系统。
- Moon/Sun 的本地主动作选择与逐帧组合，保留所有 V1 行为。
- 暂停、减弱动态、场景切换、刷新与资源复用规则。
- 非浏览器逻辑验证及用户可执行的视觉/操作检查。

### 排除

月亮对太阳作出特殊反应、日食/月食、伙伴条件事件、连锁互动、引力、伤害、热量、昼夜时间系统、真实大气散射、新行星、后处理 bloom、外部贴图/模型、物理库、新配乐、存档和相遇概率配置。

月亮、有环星球受到同一场景光源照明属于正常渲染，不算新增组合玩法。V2 不读取月亮是否结伴来解锁或强化太阳互动；关系组合留到 V4。

## 4. 三层光照行为

### 4.1 可见太阳与实际光源

可见太阳建议使用简单球体和不依赖灯光的自发光外观，例如 MeshBasicMaterial；光晕最多先用一层低成本几何/Shader。它们本身不会自动照亮 Earth。

实际照明复用 `w.sun`。它是 DirectionalLight，**改变物体距离不会自动改变亮度**。建议在 Earth 的更新中让主光位置对应太阳位置，让其 target 对应最新 `w.position`，并将 target 加入 scene、确保变换在渲染前更新。这样可见太阳、亮面方向与玩家移动的关系一致。使用 `w.position` 而不是可能滞后一帧的 `w.avatar.position`；更新后对 light 与 target 显式更新世界矩阵，Node 验证其世界坐标/方向。初始化时即同步一次，无需等玩家移动。

这会改变原先固定朝向原点的 Earth 光照，应作为 V2 的有意视觉变化记录。环境光初始保持 `1.1`，不修改全局 exposure、tone mapping、像素比、共享灯光工具或其他世界。

### 4.2 接近时的持续变化

距离使用 Earth 中心到太阳中心的三维距离。建议在外范围到内范围之间用平滑曲线计算 `proximityStrength ∈ [0,1]`，而不是叠加每帧增量：

```text
u = clamp((outerRange - distance) / (outerRange - innerRange), 0, 1)
proximityStrength = u × u × (3 - 2 × u)
targetIntensity = baselineIntensity × (1 + 0.25 × proximityStrength)
```

正常运动模式建议用 `alpha = 1 - exp(-4 × dt)`、`intensity += (targetIntensity - intensity) × alpha` 接近目标（4 的单位为每游戏秒），避免固定每帧系数；固定目标下比较相同总时长的不同 dt 划分。减少动态模式直接使用距离目标强度，不加入持续脉冲。基线强度等原值只在初始化时记录一次，不把已经变亮的值再次作为基线，否则会不断累积。

在当前强度 `3.8` 下，上述建议最大值为 `4.75`。它是待眼检初值，不是达到该数值就代表画面合格。离开外范围后，目标回到正常基线；不承诺恢复太阳加入前的旧照明方向，因为正常启用太阳时光源仍应来自太阳。

### 4.3 主动的一次回应

在可操作范围内且不处于响应/冷却时，显示“E 回应光芒”。按 E 后建议：

- 立即返回一次成功反馈，例如“光沿着你的边缘，慢慢展开。”，由既有 toast 呈现。
- 在约 3 个游戏秒内，Earth 大气产生轻微暖色变化，太阳光晕完成一次小幅呼吸，然后恢复。
- 响应结束后，恢复到**当前距离**对应的持续光照，而不是盲目恢复为进入响应时的亮度。
- 不重写 Earth 海陆贴图、不修改所有材质、不强制转镜头、不增加音效依赖。

主动作只改变既有大气的颜色与 halo 尺度，不在接近强度之外叠加主光亮度。普通模式响应权重建议 `sin(π × elapsed / 3)`，起终点为 0、中点为 1；减弱动态使用稳定权重 0.35 保持 3 秒。每帧从保存的原色/原尺度计算，结束或取消时清除响应权重，接近光照仍由当前位置单独计算。暖色建议 `#efc58b`，为待眼检初值，不改原透明度。

大气当前没有单独保存在公开字段上；如响应需要修改其 uniform，可在 `space.js` 保存现有外壳引用，不能重新创建一套大气。原始颜色、透明度和光晕尺度需有清晰归属，由同一局部更新负责计算结果，避免接近效果与主动响应互相写回覆盖。

## 5. 初始参数与可达性

以下均为建议调参起点，实施前或眼检后可以修改，但需同步范围、构图与验证。

| 参数           | 建议初值                 | 说明                                           |
| -------------- | ------------------------ | ---------------------------------------------- |
| 太阳中心       | `(-110,65,-100)`         | 放在默认视野的前侧偏左区域，具体入镜程度待眼检 |
| 太阳半径       | `18`                     | 不要求真实天体比例，不遮盖 Earth 主体          |
| 接近效果外范围 | `150`                    | 超出此距离不增加接近亮度                       |
| 接近效果内范围 | `80`                     | 在此以内达到受限最大接近强度                   |
| 主动操作范围   | `100`，中心三维距离 `<=` | 与自动对白范围、概率无关                       |
| 自动对白范围   | `120`                    | 只是向共享系统提供的空间范围，不控制发生概率   |
| 主光增强上限   | 原强度的 `1.25` 倍       | 保留暗面和界面可读性，不通过全局曝光实现       |
| 响应时长       | `3` 游戏秒               | 一次有限的视觉变化                             |
| 响应后冷却     | `5` 游戏秒               | 从响应结束或因离开外范围取消时开始             |
| 光晕响应尺度   | 原尺度最大 `1.08` 倍     | 一次缓和变化，无高速闪烁；减弱动态时不用缩放   |

以该布局，太阳水平投影距原点约 `149`，低于 Earth 移动边界 `200`；Earth 走到其下方时三维距离最小为 `65`，可进入 `100` 的主动范围和 `80` 的内范围。不能因为只比较水平距离而让高处对象变成永不可互动。

太阳高度 `65` 也为 Earth 大气半径 `24.1`、月亮半径 `9` 与太阳半径 `18` 留出几何余量，但不构成一般碰撞检测。移动速度 `38` 保持现状；检查快速穿过作用边界时无闪烁、无错过资格的假成功。

默认镜头仍为距离 `120`，缩放范围 `66–288`。不要求太阳在所有角度完整入镜；默认构图应能发现它，Earth 仍是主体。只有局部布局无法解决时才提议改共享镜头，不把改镜头作为默认工作。

## 6. 状态、恢复与访问控制

### 6.1 建议状态

```text
ready -- 有效 E --> responding -- 3 秒结束 --> cooldown -- 5 秒结束 --> ready
                         |
                         +-- 离开接近效果外范围 --> cooldown
```

精确空间边界：持续效果在 `d>=150` 为 0、`d<=80` 为 1；主动范围为 `d<=100`；响应仅在 `d>150` 时取消（等于 150 不取消）。取消发生的该次更新进入完整 5 秒冷却，不推测玩家何时跨界、也不在该帧扣冷却；正常 3 秒结束则消费实际剩余 dt。

状态可放在 `w.earthState.sun`，但必须保留 `w.earthState.moon` 的原对象身份。不要重新赋值整个 `earthState` 或重装 `attachMoonCompanion()` 来初始化太阳。

`proximityStrength` 是距离派生量，不是永久成长；响应时间、冷却时间用共享游戏 dt 累积；无穷、NaN、负值或 0 不推进计时、插值和响应包络。合法正 dt 使用现有最大 0.05 秒的控制器契约；超大外部 dt 在局部入口截到 0.05 秒，不补算后台时间。跨状态边界时将剩余 dt 用于下一状态，并以 1e-9 秒容差处理浮点边界，不能每个转换多等一帧。冷却在活动且允许模拟时继续，无需留在太阳附近。重复 E 不重新开始响应、不跳过冷却、不创建物体或回退到草招募。

### 6.2 生命周期规则

| 事件                               | V2 建议行为                                                                   |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| 接近/远离                          | 持续效果按最新距离计算；正常模式柔和过渡                                      |
| 响应期间离开主动范围但仍在外范围内 | 原响应完成，暂不重新开放太阳动作                                              |
| 响应期间离开外范围                 | 取消响应并进入冷却，局部外观回归当前距离的正常状态                            |
| 帮助/欢迎/转场                     | 不接受动作，响应与冷却计时冻结，不推进光晕动画                                |
| Earth 非活动                       | 沿用场景缓存，局部状态冻结；不把任何效果写到其他世界或全局 renderer           |
| 返回 Earth                         | 继续剩余响应/冷却时间，并以保留的玩家位置重算持续光照；不补算离开期间的时间   |
| 刷新                               | 新场景、新状态，响应和冷却重置；不写 localStorage                             |
| 太阳被禁用/移除                    | 动作查询/执行安全返回，取消局部响应并恢复保存的无太阳影响基线；不生成替代太阳 |

正常离开 Earth 不 dispose 缓存中的资源。本轮在 Earth 局部明确负责太阳可用性，不等待一个尚不存在的对象管理系统：Sun 处理器可提供内部 `setEnabled(boolean)`（无新增玩家按钮或全局概率配置）。禁用立即隐藏现有 sunBody、移除其准确 talker 记录、清除响应/冷却并恢复保存基线；重启复用同一 body/talker/材质，ready 且无重复记录。Moon 状态不变。

意外移出 scene、隐藏或引用失配时，查询/执行纯判无动作，下一次活动 Earth update（即使 canSimulate=false）执行同样清理；非活动世界无需为此另开循环。不把已移走的对象偷偷加回场景；显式重启才重新使用已持有的原对象。清理不消费 dt，是暂停的维护例外，不允许其他动画因此继续。

初始化只保存一次 V1 主光原位置/强度、原 target 引用与位置/父节点、原大气颜色、原 halo 尺度；恢复时不改这些对象身份，不将已增强值覆盖为基线。保存值与正常距离目标分别归属清楚。默认 V1 target 未加入 scene，禁用时按原父节点关系恢复，并同步世界矩阵；正常离开太阳范围则继续使用 Sun target，不恢复 V1 旧方向。

### 6.3 减弱动态效果

沿用启动时读取的 `context.reducedMotion`，不默认新增运行时偏好监听。

- 持续光照仍可反映空间关系，不加入周期呼吸或镜头运动。
- 主动响应采用一次稳定、轻微的暖色状态保持，再恢复；停止光晕缩放和循环闪动。
- 响应与冷却仍按共享游戏时间计算；V1 月亮继续固定相对偏移随行。
- 不把本次响应处理扩张为 Earth 旧自转或所有世界动画的无障碍重写。

## 7. 与 V1 回调的组合：关键实现约束

当前 `attachMoonCompanion(world, moon)` 会直接赋值：

```text
world.earthState
world.getPrimaryAction
world.onPrimaryAction
world.update
```

因此不能简单再安装一个同样覆盖字段的 Sun helper。本轮选定最小可测接法：从 Moon 逻辑提取 `createMoonCompanion(world, moon)` 返回局部处理器，原 `attachMoonCompanion` 保留为兼容包装；Sun 返回对应处理器，Earth 专用组合器安装世界三个回调一次。内部工厂只在首次建世界时调用，不在返回场景/执行 E 时重装。原 Moon 状态容器就地保留，不能用新对象覆盖。处理器的实际命名在实施 ADR 中记录，不创建全局实体框架。

**推荐的最小组合职责：**

1. Moon 与 Sun 各自管理本对象的资格、状态与更新；Earth 持有同一个局部状态容器。
2. `getPrimaryAction(context)` 使用无副作用的统一选择规则：可邀请的 Moon 优先，其次是处于 ready 且在范围内的 Sun，否则 null。
3. `onPrimaryAction(context)` 在按键当时用同一规则重新检查，只执行一个动作，返回成功反馈或 null；不能依赖之前显示过的提示。
4. `update(context)` 顺序调用 Moon 更新和 Sun 更新，各一次；始终在共享移动/边界夹取之后，读最新 `w.position`。
5. `canInteract=false` 时无主动作；`canSimulate=false` 时不推进局部动画和计时。无回调世界、草 E 路由与共享 toast 语义保持。

V1 当前只返回 `{ label }`，共享控制器没有把 action ID 传回执行端。V2 可在 Earth 内完成确定性的动作选择，无需默认扩展全局签名；若最终需要 action ID，单独说明变化、调用方和回归。

用“Moon 优先”解决潜在重叠资格，不能靠随机选择或每帧交替提示。即使初始推荐布局的两个范围不重叠，也要对调整布局后的双资格情形有稳定规则。Moon 已结伴后不会再挡住 Sun 操作；Sun 活跃/冷却也不应阻止另一处仍有效的 Moon 邀请。

## 8. 自动对白与外部相遇参数

- 给新太阳增加一个有效的 `world.talkers` 记录，名称“太阳”、正数范围、非空原创短句和来源说明；原两条对象记录仍保留。
- 提议短句可围绕受光与联系；实际内容在实现时审阅，不冒充哲学家原话。
- 太阳自动对白仍有共享 19 秒冷却和随机候选选择，可能没有立即出现，也可能被其他对象选中。
- E 的成功反馈沿用主动作结果，不调用 `say()`、不改 `lastTalk`、不绕过共享冷却抢占对白区。
- 不新增 Earth 专用相遇概率、生成计时器或强制太阳开场对白。外部参数归属不变，若控制太阳是否存在/允许互动，则资格和视觉影响应尊重其结果。
- 响应后的 5 秒仅是太阳主动动作的重复保护，不得把它复用成自动对白冷却或相遇频率配置。
