## 1. 体验目标

V1 建立关系，V2 感受光照，V3 已提供有限运动影响。V4 验证：**同一个相遇，因为玩家之前的选择，产生不同的回应。**

```text
独自接近 Sun → E 回应光芒 → 沿用 V2 的独自回应

先邀请 Moon → 带它接近同一个 Sun
           → E 与月亮回应光芒
           → 同一次回应中，Moon 也出现可辨认变化
           → 响应结束，继续原有探索与同行
```

两个天体同时被灯光照亮不等于组合完成。未邀请和已邀请两条路径，应在提示、成功反馈及 Moon 局部响应上可区分。

玩家无需先完成太阳任务、听过指定随机对白、体验引力或精确排列天体。独自回应仍完整可用，Moon 结伴不是通关钥匙。保留自由漫游、无分数、无强制任务的定位。

## 2. 依赖与真实基线

```text
V1：原 Moon 结伴 ──┐
                   ├─ V4：Sun 回应的 Moon 合奏变体
V2：原 Sun 回应 ──┘

V3：运动影响 ─────── 保持兼容，不是本组合的技术前置条件
```

V4 直接依赖 V1/V2；当前 V3 已实现，必须保留其最终位移、边界与中止语义，不重建牵引状态或移动接口。

| 当前位置           | 已有能力                                                                                      | V4 处理                                           |
| ------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `earth-moon.js`    | `createMoonCompanion()`，原 Moon 引用、`earthState.moon.status/phase`                         | 读取真实关系和对象身份，不重新安装或重建 Moon     |
| `earth-sun.js`     | `createSunResponse()`，ready/responding/cooldown，3 秒回应、5 秒冷却                          | 同一次回应选择变体，保留唯一计时和原取消规则      |
| `earth-actions.js` | `installEarthActions()`，Moon → Sun → 有环星球优先级；ringed → moon → sun → visualUpdate 更新 | 合奏属于 Sun 变体，不新增竞争 E 的独立候选        |
| `space.js`         | Earth、Moon、有环星球、Sun 球体/halo、Earth 大气                                              | 保留四个主要天体与三条 talker，不新增组合专用副本 |
| 共享控制器         | label/null、反馈文本/null、统一 context、唯一 RAF                                             | 默认不改变输入、镜头、移动、共享签名或对白调度    |

实施时核对最新工作区，不根据旧规划中的“Sun 未实现”重建现有系统。实际 V2 契约见 ADR 0003，验收状态见 V2 QA。

## 3. 范围

### 包含

- Sun 动作开始前检查 Moon 是否真实结伴。
- 同一 Sun 动作的 solo/duet 两种提示、反馈和局部视觉。
- 一个 3 秒响应包络同时驱动 Sun 原表现与 Moon 附加变化。
- 失效、取消、暂停、返回、刷新、减弱动态的处理。
- 一个页面内组合完成标记，不显示分数或成就。
- 前序逻辑回归、用户两条路径的对照检查。

### 排除

新天体、第二个月亮/太阳、额外灯光、真实日食/月食、影子投射改造、轨道对齐谜题、自动重排、镜头演出、伙伴队形、多组合事件、图鉴、成就、保存、新音效、AI 对话、通用事件总线及相遇概率实现。

有环星球不参与本组合。Moon + 星环共舞、引力对伙伴的特殊影响、按互动历史改变对白都留作独立候选，不能在 V4 顺带加入。

## 4. 条件与主动作

### 4.1 合奏条件

Sun 满足原操作资格，同时：

- `world.earthState.moon.status === 'orbiting'`。
- 当前控制的是初始化捕获的原 Earth Group（`world.globe.parent`），按对象身份校验，不按 kind。R 已能接管其他天体，`world.position/avatar` 不再永久表示 Earth。未登记 controlled 的独立工厂按原 avatar 身份校验；运行时不以缺省分支绕过身份失配。
- `world.moon` 指向结伴模块管理的原 Moon，仍在原 scene、Moon 与 scene 可见，且材质仍是初始化捕获的原材质。当前没有通用对象禁用接口，不伪造该接口。
- 参与者身份没有因替换 Mesh 而失配。

不能只检查距离：未邀请但很近的 Moon 不触发合奏。也不能把 `moon.invitable=false` 当成伙伴不存在；invitable 控制邀请资格，不是通用存在/可见标志。

Moon 不必也进入 Sun 的 100 单位操作范围；这个范围约束玩家 Earth。Moon 的附加色彩是风格化关系回应，不宣称天文学真实性。

### 4.2 提示与执行

| 当前资格                           | 建议提示           | 成功反馈                             |
| ---------------------------------- | ------------------ | ------------------------------------ |
| Sun 可用，没有有效伙伴             | `E 回应光芒`       | 沿用 V2 独自反馈                     |
| Sun 可用，有效 Moon 已结伴         | `E 与月亮回应光芒` | 例如“这一次，光也照见了你的同行者。” |
| Sun responding/cooldown 或共享阻挡 | 无 Sun 主动作      | 无新反馈、不叠加回应                 |

可邀请 Moon 继续享有原优先级。Sun 两种变体不同时列为两个候选，不增加快捷键或菜单；保持当前 V3 已有动作选择规则。

查询无副作用，按 E 时重新检查。旧提示是 duet、但 Moon 已失效时，若 Sun 仍可用则执行 solo，返回实际反馈，不能强造伙伴来兑现旧提示。

## 5. 视觉：共用包络，各自拥有字段

Sun 模块继续唯一负责 Earth 大气颜色、Sun halo 尺度和原响应时钟。关系模块不在另一个 update 重写相同 uniform，不额外抬高主光强度或突破 V2 上限。

建议给**原 Moon 材质**增加一次轻微暖色/自发光变化：

- 保存实际修改字段的原值，复用原 Mesh/Material，不 clone 第二个月亮。
- 使用 Sun 同一个归一化响应进度，开始/结束回到基线，中段柔和变暖。
- 建议暖色附加 emissive 贡献峰值为 `1.2`，只是待眼检初值。按原 emissive 颜色与 intensity 的有效贡献保存/恢复，不能仅把默认 intensity 加 `1.2` 后配上满强度暖色；Moon 不能变成另一颗太阳。
- 不改变位置、轨道半径/速度/相位，不为了展示强行把 Moon 从 Earth 背后拉出来。
- 短暂自然遮挡可接受；正常拖动观察应能看出一次不同回应。

不使用全屏闪光、光束网络、剧烈脉冲或额外粒子。Moon 的色彩附加表现不是地影或日食计算。

结束时恢复 Moon 材质基线，Sun 恢复**当前距离**对应的正常照明，不回写旧 Earth 位置或清空结伴。若未来其他功能也写 Moon 材质，需明确一个局部合成入口，不能互相恢复成不同基线；本次不预建通用效果堆栈。

## 6. 状态、完成与取消

### 6.1 一次动作锁定变体

```text
ready
  └─ 有效 E：锁定 solo 或 moon-duet 与原参与者
       → responding（原 3 秒）
       → cooldown（原 5 秒）
       → ready
```

variant 在 E 接受时确定，不能每帧改变。Sun 独自回应进行到一半才邀请 Moon，本次仍是 solo；下一次有效 Sun 动作才可 duet。

建议在 Sun 原子状态中增加必要的变体/本次回应标识，在 `earthState.relationships.moonSun` 保存附加响应与 `hasCompleted`。字段名是提案；不重建整个 earthState 或 Moon/Sun 子状态。

### 6.2 完成必须区别于取消

- 只有完整自然结束且原 Moon 本次始终有效，才置 `hasCompleted=true`。
- 成功 toast、接受 E 或进入 cooldown 都不自动算完成；V2 远离取消也会进入 cooldown。
- 标记是页面内布尔值，重复完成不计分，刷新清空，不增加图鉴/保存。
- R 换到其他身体：不再满足本次 Moon 合奏资格，恢复 Moon 附加视觉并标记本次退出；Sun 沿用既有时钟与独自部分，返回原 Earth 不重入同一回应，下次有效 E 才可再次 duet。V4 不重写原 Moon 跟随当前身体中心的既有逻辑；其与 R 控制 Moon 的位置所有权风险单列，不宣称已修复。
- Moon 中途失效：清理其附加材质，取消本次 Moon 参与，Sun 按原规则继续独自部分；本次不计 duet 完成。对象恢复也不在同次回应重新加入。
- Sun 失效：取消整个回应并清理 Moon 附加外观。本次不计完成，不清空过去已真实完成的标记。
- `hasCompleted` 记录程序过程完整结束，不证明用户已经注意到画面差异。

### 6.3 生命周期

| 事件            | 行为                                                          |
| --------------- | ------------------------------------------------------------- |
| 连按/长按 E     | 原 repeat/非 ready 保护；一次反馈，一个回应，一个完成处理     |
| Earth 移动      | Moon 原轨道/随行、Sun 原距离受光照常工作，无新自动位移        |
| 超过 Sun 外范围 | 沿用 V2 取消并完整冷却，Moon 清理，本次不计完成               |
| 帮助/欢迎/转场  | 阻挡新动作，冻结进度；失效维护清理仍可执行                    |
| Earth 非活动    | 缓存状态，不推进、不补算离开时长                              |
| 返回            | 先重查原参与者，再继续剩余回应，无新 E/反馈                   |
| 刷新            | Moon 独立、Sun 初始、关系标记重置                             |
| V3 牵引         | 最终位移后再更新关系；牵引导致超出 Sun 范围时自然按原规则取消 |

## 7. 局部接口：不复制 Sun 时钟

已提交 Sun 基线返回动作、update 和 setEnabled；本轮接续已有未提交草稿，已接入 `selectVariant`、responseId/variant/lastEnd 和 `getResponseView(reducedMotion)`，已由 space/actions 接线；具体测试与未验证项见 QA 记录。只读 status 无法区分自然完成与取消，不能凭 responding→cooldown 猜成功。

沿用草稿的最小回应视图 `{id, variant, responding, weight, lastEnd}`，不另建生命周期通知或事件总线。视图为复用的借用只读对象（不是不可变快照），关系直接消费 Sun 的 weight，不增加 progress/时钟；结束记录按 id 去重：

| 必要信息                         | 用途                                             |
| -------------------------------- | ------------------------------------------------ |
| 本次回应标识                     | 同一 E 不被多个 update 误当新事件，不要求全局 ID |
| 接受时锁定的变体/参与者          | 不从旧提示或每帧距离重建本次关系                 |
| Sun 包络 weight、是否 responding | 复用唯一 remaining/包络，不累计第二份时间        |
| 自然完成/远离取消/失效取消原因   | 正确恢复并更新 hasCompleted                      |

建议调用顺序：

```text
实际最终移动（V3 先完成影响与夹取）
  → Moon 原轨道更新
  → Sun 唯一时钟、受光与原响应
  → 关系模块读取本次结果，更新/清理 Moon 附加材质
  → 镜头、提示、共享相遇 → render
```

也可在 Sun 局部响应合成阶段调用关系适配，前提是职责清楚、两对象各更新一次。跨 dt 状态边界时完成/取消仍只能处理一次，不能漏掉末帧或重复完成。接受 Sun 动作后同步一次关系视图（dt=0、不再调用 Sun.update），保证动作当帧及减弱动态表现一致；逐帧关系更新仍在 Sun 之后、visualUpdate 之前。

V2 暂停时仍可维护性清理失效对象，V4 应继承，不能把恢复藏在 canSimulate 分支之后。Moon detach/材质替换时仍恢复自己持有并写过的原材质字段，不覆盖新材质、不把旧材质重新赋回 Mesh、不重新挂回旧对象。直接禁用 Sun 后，Moon 在下一次关系维护调用清理，不声称 Sun 内部方法会同步通知关系模块。

默认不改 main/context 或共享 label/null、反馈文本/null。局部契约变化按规则写 ADR，保持原调用兼容性。接口已按 ADR 0006 实施；未声明浏览器手验通过。

## 8. 减弱动态、对白与配置

- 沿用启动时系统偏好。Sun 使用 V2 稳定暖色、不缩放；Moon 稳定轻微色彩保持后恢复，不脉冲或加速轨道。
- 两模式使用同一个 3 秒过程和完成规则，不能通过禁用整个组合让测试通过；V1 固定偏移随行继续生效。
- 保留三条既有 talker，不为合奏创建第四条影子对白记录。
- 主动反馈通过 toast，不调用 say/修改 lastTalk，不强制自动对白。
- 不要求先随机听见指定内容，不实现概率/密度/生成策略；对象配置禁用参与者时尊重结果，不制造“必遇组合”。
- 沿用 Sun 5 秒冷却，不加关系随机触发器。无运行时新监听、音频上下文、RAF 或定时器。

## 11. 用户浏览器对照检查
