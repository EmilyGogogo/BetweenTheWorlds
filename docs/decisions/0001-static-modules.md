# 0001：将原始 Demo 整理为静态模块协作基线

- 状态：接受，作为本次仓库初始化的实施基线；团队可通过后续决策替代
- 日期：2026-10-17
- 依据：用户提供的试玩说明、HTML 和搭建协作仓库的请求

## 问题与约束

原始 HTML 内嵌样式、全部游戏逻辑和 base64 引擎，单文件易试玩，但多人修改难以审阅和划分责任。现有功能无需后端，且离线运行是材料中的明确能力。

## 决定

保留两个原始附件，用哈希记录来源；开发版拆成原生 ES Modules、独立 CSS、四个场景模块和共享工具。保持 Three.js r170 的原字节版本，补齐官方 MIT 许可。本次不增加前端框架或升级引擎。

开发工具使用锁定版本的 ESLint、Prettier、Playwright，Node.js 原生测试和小型静态服务。发布脚本只复制明确列出的运行文件到 `dist/`，不把协作资料、历史 Demo 或本地秘密带入发布产物。

## 权衡与验证

优点是保留当前行为、减少初始依赖与迁移成本、便于按场景分工。代价是没有热更新与压缩，静态服务需要维护；当模块或资源管线的真实需求出现时再评估打包器。主控制器仍有后续拆分空间。

通过仓库完整性检查与真实浏览器冒烟验证模块接线、进入世界、四层切换、移动、同行、帮助、声音和刷新重置；画面质量与性能仍需人工试玩。CI 与人类审阅共同约束提交，规则文档本身不能强制所有 AI 客户端服从。
