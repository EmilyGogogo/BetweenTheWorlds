# 0003：人层的其他人与更多动物

- 状态：提议
- 日期：2026-10-17
- 关联任务与参与者：用户在 `feature/human` 分支提出的“增加更多人和动物，有不同状态、不同类型的人物和多样的动物”；AI 协助实现，待人类审阅。建立在 0002 的人物视角与动物观察之上。

## 问题与约束

人层此前只有玩家可操控的五位人物和八种小型动物，原野上没有别人。需求是加入不同类型（老人、大人、孩子、幼儿；牧人、画家、旅人、巡护员等）和不同状态（走路、坐、睡、干活、玩耍，以及对玩家的各种反应）的人物，并大幅增加动物种类。约束沿用 0002：离线静态运行、内容与逻辑分离、重要行为可回归测试、主控制器不继续膨胀。

## 考虑的方案

1. 把其他人当作只会说话的 `talkers`：改动最小，但没有状态、日程和姿势，不满足“不同状态”。
2. 把其他人塞进动物状态机：可复用逃跑、跟随等逻辑，但人的日程（去水塘、拾柴、画画）和反应（打招呼、躲到同伴身后）与动物脾性差异太大，会让 `wildlife.js` 变得难懂。
3. 按 0002 的分层另建一组模块：`content/residents.js` 描述人与日程，`core/residents.js` 执行日程与反应，`worlds/residents.js` 负责体态与姿势；`fieldwork.js` 只在更新、观察和提示处接入。动物侧在 `wildlife.js` 中增加少量通用反应（`fly`、`warn`、`tame`、注视距离、跟随带头者）。

## 决定与理由

采用方案 3。日程是一串可循环的步骤（沿路点走、原地做事、在一片范围内来回），足以表达九个人的一天，又不必引入通用行为树。人体复用 `people.js` 的模型，只把上身与头改为关节组，玩家形象不受影响。家畜和幼崽通过栖息地的 `follow` 与动物 `leader` 跟随居民或母兽，避免为“羊群跟着牧人”单独写一套逻辑。

为保持内容可信：自然知识采用常见科普事实，尚有争议的写明“有研究认为”；母象只警告、领幼崽离开，不攻击玩家，符合项目“低打扰、无对抗”的方向。

## 影响与验证

- 接口：人层场景状态新增 `residents`、`residentViews`、`pondLevel`；`person()` 的 `userData` 新增 `torso`、`head`、`hands`，`createPeople()` 导出 `binoculars`；`createFauna().spawn()` 接受 `scale`；栖息地可带 `id`、`follow`、`scale`；物种可带 `reactionNotes`、`trackless` 与 `temperament.perch`。
- 资源：居民、新动物、水塘、小屋、岩丘与灌木随人层首次进入时创建并常驻，与现有缓存策略一致；没有新增事件监听或音频资源。
- 回退：删除三个 `residents` 模块与对应测试，还原 `human.js`、`fieldwork.js`、`people.js`、`wildlife.js`、`fauna.js`、`animals.js` 的增量即可。
- 验证：`tests/unit/residents.test.mjs` 与 `tests/unit/wildlife.test.mjs` 覆盖日程、反应与新行为；人层浏览器冒烟覆盖新内容不引入运行错误；姿势、模型观感与性能需人工试玩，绘制调用的观察值记录在 `docs/architecture.md`。
