# 0002：Earth V1 主动作与局部更新接入

- 状态：接受为本轮本地实现契约；依据用户明确授权执行全部 V1 步骤，不表示其他贡献者已审阅或合并
- 日期：2026-10-17
- 关联：Earth V1，`A11Y-02`、`PERF-01`、`DESIGN-01`
- 依据：用户已确认此前移动检查通过，并明确要求完成 V1 全部实现与非浏览器 QA；仅到手动浏览器 QA 时暂停

## 问题与约束

已有月亮和对白，但共享主循环没有世界回调，E 仅供草招募。需要一次主动邀请和持续结果，继续静态离线运行并保留唯一 RAF。用户允许单纯提高 Earth 固定速度；此次选择 `19 → 38`，草、人、岛及原移动边界不变，无需新加速度状态。

## 考虑的方案

1. 在主控制器硬编码 Moon 的全部逻辑：改动入口少，但共享控制器承担更多 Earth 状态和测试负担。
2. 三个可选世界回调：主控制器保留输入/UI/时钟，Earth 管理资格、两态和轨道。为本次实现方案。
3. 通用交互/事件/实体框架：当前单对象不需要，增加接入与回归成本。

## 决定与理由

沿用实施计划的 `getPrimaryAction(context)`、`onPrimaryAction(context)`、`update(context)`，各自用于纯查询、重新验证后执行、逐帧更新。`context` 含 `canInteract`、`canSimulate`、`reducedMotion` 及更新用 `dt`；只对活动世界调用，未提供入口则保留原行为。执行结果为成功反馈文本或 `null`，不通过 UI 提示缓存决定动作。

顺序为输入移动/边界夹取 → 世界更新 → 镜头同步 → 提示/原相遇检测 → 渲染。Moon 读 `w.position`；原 Earth 自转留在现有一处。Moon 保持 scene 子节点和 talker 身份，缓存局部状态，非活动暂停。

主动邀请不等待随机对白。当前没有外部概率配置；未来若配置禁用或移除 Moon，资格需尊重该结果，不创建替代对象。Earth 不新增随机对白计时器。

## 影响与验证

接入涉及 `main.js`、`space.js`、必要 UI 与专用逻辑/测试模块；其他世界回调保持可选，草仍走 recruit。执行实施计划步骤 1–9，尤其验证输入阻挡、过时提示、幂等、最新中心、暂停和减弱动态组合。

本轮按用户授权实现上述共享控制器与 Earth 接入；新增 `src/core/world-actions.js` 仅提取可测试的动作分派、context 条件和提示 DOM 适配，不增加事件框架。现有世界缓存、移动规则、Earth 单处自转、对白冷却不变；草最近对象判断从 encounter 移至逐帧提示查询，并在执行时刷新，避免共享提示失效。

Node 模块/接口与仓库检查结果见 [V1 QA 记录](../earth-v1-qa-results.md)；用户浏览器检查仍待执行。量化性能阈值未接受，不由本 ADR 设为已达标；未提交、推送、合并或部署。
