# Earth V2：实施分步与 QA 门槛

日期：2026-10-17。基线：已提交 V1 `9dc2970`。依据：[修订后的 V2 设计](earth-v2-plan.md)、[当前架构](architecture.md)、[ADR 0002](decisions/0002-earth-v1-integration.md)。状态：本轮已按用户授权实施，非浏览器结果见 [V2 QA记录](earth-v2-qa-results.md)；用户已明确确认S1–S7浏览器检查通过，见QA记录末尾。本文门槛的通过依据分别为代码证据与用户报告。

## 1. 范围、默认值和 QA 分工

目标：只新增一个 Sun；靠近时光照改变，E 产生一次大气/光晕回应。与月亮结伴无依赖，保留原 Moon、有环星球、速度 38、移动边界 200、镜头和共享输入。无取消月亮、引力、伤害、日食、后处理、外部素材、存档或新音频。

| 参数 / 行为           | 实施起点                                                                     |
| --------------------- | ---------------------------------------------------------------------------- |
| Sun 位置 / 球半径     | `(-110,65,-100)` / `18`；body 为 scene 下的独立引用                          |
| Halo                  | 最多一层，建议基础半径 `24`；原尺度 × `(1+0.08×responseWeight)`，不常驻呼吸  |
| 距离增强              | 内 `80`、外 `150`，三维中心距离，smoothstep 权重                             |
| 主光强度              | 原值 `3.8` 到最多 `4.75`；环境光仍 `1.1`；不动全局 exposure                  |
| 插值                  | 普通模式 `alpha=1-exp(-4×dt)`；减弱动态直接用距离目标强度                    |
| 主动作 / 自动对白范围 | `d<=100` / `120`，语义独立                                                   |
| 响应 / 冷却           | 响应 `3` 游戏秒，结束后冷却 `5` 游戏秒；均仅在活动且允许模拟时推进           |
| 普通响应权重          | `sin(π×elapsed/3)`；只驱动原大气颜色与 halo 尺度，不额外抬主光               |
| 减弱动态响应          | 暖色权重 `0.35` 稳定保持后恢复；不缩放 halo；Moon 保持 V1 固定偏移           |
| 暖色建议              | `#efc58b`，与原大气颜色插值；不改原透明度                                    |
| 动作冲突              | 可邀请 Moon 优先，其次 ready 且范围内的 Sun；不随机轮换                      |
| 离开外范围            | `d>150` 才取消响应，立即进入完整 5 秒冷却；`d=150` 不取消                    |
| 日常 QA               | Codex 无浏览器检查；用户按 [手动检查单](earth-v2-manual-qa.md) 验证显示/控制 |

布局与亮度是明确的试玩起点，用户眼检后可局部调参；未测量不宣称画面或性能合格。无需再次询问是否跳过浏览器自动化：用户已明确指定。Codex 不启动/控制浏览器，不运行/新增 E2E、不下载浏览器；已有 E2E/CI 不删除、不禁用。每次实施交付运行 `npm run check`，报告非浏览器证据和待用户项。

### 可选性能与内存专项的配置边界（本次反馈修订）

量化性能与泄漏诊断是 **两次独立运行**，不混用结果。性能运行使用实际演示设备的普通浏览器配置，无 expose-gc、强制 GC、heap profiler 或自动化；记录真实帧时间。内存诊断另开会话，用户可使用 DevTools 的 Collect garbage（如支持）；不假设普通页面有 `window.gc()`，不要求为日常手验加启动标志。若确需特殊启动参数或其他诊断机制，单独记录，并仅用于诊断，不拿该会话帧率代替正常性能基线。

普通浏览器无法提供可靠强制 GC/heap 读数是预期情况，不是罕见故障：记“heap 专项未验证”，保留 Node 对象引用证据，不强行完成 floor-to-floor 比较、不声称无泄漏。能采样时才执行 3 个预热参考 + 10 次往返后 GC 样本，比较下界/前后组中位数，增长需复测与保留路径证据。Codex 只离线分析用户提供的数据，不控制浏览器。两个专项均可选，不阻挡本轮独立代码实现。

## 2. 具体文件与接口

| 文件                                                              | 必要变化                                                                                        |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/worlds/space.js`                                             | 保存现有大气引用；创建一次 Sun body/halo/talker；复用主光；安装组合回调                         |
| `src/worlds/earth-moon.js`                                        | 提取返回处理器的工厂，保留 attach 包装与原业务；状态只合并 moon 字段，保留已有容器/状态身份     |
| `src/worlds/earth-sun.js`（新增）                                 | Sun 两类视觉效果、三态/计时、资格和启停清理；无 DOM、时钟、全局输入                             |
| `src/worlds/earth-actions.js`（新增）                             | Earth 专用小组合器，确定性优先级、一次执行、Moon→Sun 各一次更新；不推广成实体框架               |
| `tests/unit/earth-sun.test.mjs`、`earth-actions.test.mjs`（新增） | 距离/状态/恢复/组合接口与真实 Three.js 对象验证                                                 |
| `tests/unit/earth-moon.test.mjs`                                  | 保留所有旧行为断言；实际工厂精确库存由 2 条 talkers 更新为 3 条，保留原两条内容、范围和身份检查 |
| 文档                                                              | 新 ADR、架构、README、QA 结果/用户检查单；仅在必要时增加帮助的一句 Sun 说明                     |

不默认修改 main、core/world-actions、其他世界、移动参数、全局样式、renderer、服务/构建/CI/依赖/引擎/原型。若实施确实需要越界，先说明具体缺口与测试影响；不借计划顺便重写。已有 shared context 和 label/null、feedback/null 返回契约足够承载 V2。

局部工厂创建处理器但不安装 world 回调；兼容 `attachMoonCompanion()` 仍可用于 V1 独立测试。V2 初始化流程：保留 `earthState` 容器 → Moon 工厂一次 → Sun 工厂一次 → Earth 组合器安装三个可选回调一次。新建世界时才创建模型/材质/处理器；E、update、返回世界均不得重装。

```text
main（保持现状）
  移动/边界夹取 w.position
    → world.update(context)
         → moon.update(context) 一次
         → sun.update(context) 一次
              可用性维护 → 暂停判断 → 距离/目标 → 时间状态 → 视觉派生值
    → placeCamera → 现有提示/对白 → render

查询 / E 执行当时
  canInteract? → 可邀请 Moon? → Moon
                        否 → 可回应 Sun? → Sun
                                      否 → null
```

Sun 启停是内部生命周期接口（如 `sunActions.setEnabled`），不增加玩家菜单或外部概率系统。Moon 与 Sun 局部状态互不读取以解锁效果；组合器只负责优先级和调度。

## 3. 逐步实施与必须通过的代码 QA

每步记录 Pass/Fail、测试名/命令和证据。前置代码失败先修复；用户尚未操作记“待用户”，允许继续独立代码工作。不得将 Node 验证写成渲染/输入事件验收通过。步骤表达依赖，不要求拆成多个 PR；只创建而未安装的 Sun 模块不算功能完成。

### 步骤 0：冻结 V1 基线与本轮契约

工作：检查 status/diff，保留 V2 文档及 README 已有工作；记录 HEAD、19 项 V1 测试、现有三天体与两 talkers、光源与大气。将本文的组合方式、dt/边界/启停规则写入实施 ADR。参数为本文默认值，不虚构其他贡献者审阅。

QA：

- **0-A｜Codex**：Node `>=22.13 <23`，实施前 `npm run check` 通过；测试数量/实际结果入记录。不得把 V1 当作未提交或重新实现控制器。
- **0-B｜Codex**：列出 w.sun 原位置/强度/target 引用/父节点、大气原 uniform 与 Moon 状态；确认只新增 Sun，不增加灯光副本或第二套大气。
- **0-C｜用户状态**：保留 V1 原移动检查已确认的事实；V1 的 Moon 手验已由用户明确确认通过。V2 手验包含 V1 邀请路径，不要求先重复全套浏览器测试才准备代码。

### 步骤 1：先解除 Moon 的独占安装，建立 Earth 组合器

工作：保留 Moon 业务与 attach 包装；提取返回处理器的入口，Earth 安装组合回调。新增 Sun 真实消费者在步骤 2–3 接齐后才算交付，不合并不会被调用的空 hook。

QA：

- **1-A｜Codex**：所有旧 Moon 独立逻辑测试继续通过，包含距离、一次邀请、原 Mesh、相位、暂停、减弱动态；既有 earthState 与 moon 状态对象身份不因初始化 Sun 或组合安装而改变。
- **1-B｜Codex**：组合器用可控处理器测试，双资格恒定选 Moon；Moon 不可邀请才选 Sun；Sun responding/cooldown 不阻止仍合格的 Moon。查询无状态副作用；E 当时重新选，不信上次提示；每次只执行一方，20 次重复执行不绕过各自规则。
- **1-C｜Codex**：传同一个 context/同一 dt，每次 world.update 恰好按 Moon→Sun 顺序各调用一次；canSimulate=false 仍传递以允许 Sun 可用性清理，但两者不得推进动画/计时。共享路由 tests 不变，无额外 RAF/监听。
- **用户**：阶段完成后不需要中途浏览器检查；最终 S5/S7 覆盖接线。

### 步骤 2：新增一次性的 Sun 场景资源与保存基线

工作：在 space 创建 body（BasicMaterial 自发光外观）和最多一层 halo，保存 `w.atmosphere` 的原壳引用。Sun 追加一条原创 talker。保存将被修改的值一次；light.target 使用原引用并加入 scene，而不是创建另一个 DirectionalLight。处理器消费实际 Three.js 对象。

QA：

- **2-A｜Codex**：真实 Earth 工厂得到恰好四个主要天体引用、恰好三条 talkers，原 Moon/有环星球及其内容/范围保留，新增一个 Sun talker，Sun 球半径 18。Halo/光源不重复计为独立天体。
- **2-B｜Codex**：Sun 在指定坐标；在可移动圆盘内存在 `d<=100` 与 `d<=80` 的点，垂直最短距离 65。按实际模型验证 Earth 最小中心距离 65 >24.1+18，Moon 对 Sun 的最低垂直差至少 60 >9+18；不宣称引入碰撞系统。
- **2-C｜Codex**：用真实 transform 检查 light 位置等于 Sun 世界中心，target 等于最新 w.position 且属于 scene；avatar 故意留旧位置仍正确。显式同步 world matrices 后检查方向，禁止只看 position 属性。
- **2-D｜Codex**：基础几何/材质/纹理/光源与原色副本只初始化一次；无 loader、网络、额外 AudioContext；纹理绘制 Node stub 不作为图像证据。
- **用户 S1/S6**：最后查看是否可辨认、主体/暗面清楚及 halo 排序，不要求现在启动浏览器。

### 步骤 3：距离增强与稳定基线恢复

工作：用三维距离算 smoothstep 权重和有界目标强度；从原强度导出目标，再按 dt 插值。原大气/halo 的 responseWeight 此时为 0。原曝光、环境光、Earth 贴图不变。

QA：

- **3-A｜Codex**：`d=79.999/80/80.001`、`149.999/150/150.001`，权重有限且在 [0,1]，单调；`d=115` 得 0.5；同 X/Z、不同 Y 会改变结果，不能用水平距离替代。
- **3-B｜Codex**：强度始终 [3.8,4.75]；长时间近处更新不叠加；远处充分更新后回归 3.8（明确数值容差，不要求有限时间严格相等）。固定目标下用 0.01/0.025/0.05 的相同总时长比较插值结果，容差 1e-6。
- **3-C｜Codex**：减弱动态直接使用距离目标，无常驻 halo 呼吸；正常 d>=150 只回到基线强度，light 方向继续来自 Sun。禁用恢复 V1 原方向由步骤 5 单独测。
- **3-D｜Codex**：目标按最新 w.position 计算；不写 renderer、camera、其他世界或 Moon 状态；方向在首次渲染前已同步。
- **用户 S2**：最终检查靠近/退开时亮度与方向是否可信、有无过曝，Node 只能证明参数和方向数学关系。

### 步骤 4：主动回应、冷却和状态恢复

工作：加入 ready→responding→cooldown→ready。ready 且 d<=100 可 E，返回一次 toast 文本；普通响应权重为单次 sin 包络，减弱动态为稳定暖色保持。响应只写大气原色派生值和 halo 原尺度派生值，不影响主光增强上限。

QA：

- **4-A｜Codex**：`99.999/100/100.001` 的操作资格、缺失/禁用、canInteract=false、已响应/冷却均正确；先查询后移动到范围外，执行必须失败、不反馈、不改状态。动作不依赖对白或 Moon 结伴。
- **4-B｜Codex**：第一次有效 E 仅一份反馈；之后 20 次执行不重置时间/创建资源；共享 repeat 过滤依旧有效；动作只返回反馈，不改 say/lastTalk/共享 19 秒冷却。
- **4-C｜Codex**：正常响应 3 秒、其后冷却 5 秒，按 1e-9 秒容差检查边界前/到达/后；合法跨界 dt 的剩余时间继续消费，不丢一帧。NaN/Infinity/负/零 dt 不推进时间/插值/包络；过大 dt 只推进最多 0.05 秒，不瞬间跑完。
- **4-D｜Codex**：elapsed=0/1.5/3 的普通权重为 0/1/0；每次基于原色/尺度重算，不累积漂白或缩放；主光仍<=4.75。响应结束时原色/尺度恢复，主光目标使用结束时的距离，不读“触发时亮度快照”。
- **4-E｜Codex**：响应时到 100<d<=150 仍完成；d=150 不取消，d>150 取消并开始完整 5 秒冷却，取消帧不扣冷却。回到范围内也不能绕过冷却；冷却可在远处推进。
- **用户 S3/S4**：最后验证反馈、效果可分辨、连按/按住无重复，以及离开/再进入的控制结果；精确秒数由 Codex 测。

### 步骤 5：暂停、缓存、减弱动态与 Sun 可用性清理

工作：Earth 不活动就不更新；帮助/欢迎/转场不推进响应、冷却、插值或 halo。Sun 的启停/移除清理单独处理，避免暂停阻止恢复原值与移除幽灵对白。

QA：

- **5-A｜Codex**：responding 与 cooldown 各暂停多次 dt 后，剩余时间/外观不变；恢复只用当前合法 dt，无全局 time 推导或离开时间补算。代码审查继续使用 V1 缓存；新工厂才重置状态。
- **5-B｜Codex**：同一组合测试开启 reducedMotion，移动 Earth 两轴/斜向：Moon 相位不变且三分量偏移保持；Sun 距离强度仍正确、响应颜色稳定、halo 原尺度始终不变；3 秒结束后恢复原色并进入冷却。
- **5-C｜Codex**：ready/responding/cooldown 分别调用内部 disable，立即隐藏原 body、移除精确 Sun talker、重置为 ready、恢复 V1 主光原位置/强度/target 父节点与位置、恢复原色/原尺度；Moon 状态与原两条 talkers 不变。重启复用同一对象/材质/记录，不重复 push。
- **5-D｜Codex**：Sun 意外 detach、hidden 或引用失配时 query/action 无副作用地返回 null；下次活动 update，即使 canSimulate=false，也清除 Sun 影响/幽灵 talker，不推进计时或偷偷重建/重新挂载 body。显式重启才恢复原对象。
- **5-E｜Codex**：保存基线的快照在重复 enable/disable/E/update 后未被“当前增强值”污染；transform/Color/Vector3/材质引用保持身份，更新不新分配资源。正常远离与禁用的方向恢复测试分开。
- **用户 S4/S5/S6**：最终验证暂停/切换/刷新、两条体验路径、减弱动态。disable 是内部生命周期 API，无需用户用控制台调用私有状态。

### 步骤 6：完整非浏览器回归、构建与资源证据

工作：用实际工厂、局部处理器和共享动作适配一起走邀请/回应/冷却/暂停/启停路径；执行规定检查。接齐处理器消费者后才报告功能代码就绪。

QA：

- **6-A｜Codex**：`npm run check` 全通过，V1 全部业务断言保留；库存断言精确更新为原对象+一个 Sun，而非放宽数量。原服务器/原件/链接/格式/lint 检查保留，构建后新模块可导入且发布文件与源码一致。
- **6-B｜Codex**：实际工厂中先 Moon 后 Sun、独自 Sun、Sun 响应中邀请仍合格 Moon 均通过；特制布局测试双资格/动作优先级，不要求用户改场景或传送来测重叠范围。
- **6-C｜Codex**：重复 100 次响应/冷却及 10 次启停/模拟缓存重用，记录 scene 对象、geometry/material/texture 引用集合与 talker 记录；正常启用状态集合不持续增长，禁用仅改变约定的存在/挂载项。禁止将此结果写成实际 GPU/heap 无泄漏。
- **6-D｜Codex**：新场景 Sun ready、计时归零、Moon available；既有会话 world/state 引用未被动作/返回重装。main/共享路由/其他世界/移动参数不变或每处例外有具体理由。
- **用户 S7**：最终做控制、草招募、声音、提示串场与 2–3 分钟实际流畅度回归；量化 FPS/heap 只在需要时另测。

### 步骤 7：文档、结果与用户手验交接

工作：同步实际接口、参数、禁用恢复、QA 证据和限制；建立实施结果文件，并列用户需要检查的 S1–S7。V1 手验按用户本次明确确认记 Pass；V2 修改后的 Moon/Sun 组合仍需用户回归，不能沿用旧结果自动通过。

QA：

- **7-A｜Codex**：每个 0-A～6-D 门槛有结果/测试名或代码审查范围；没有浏览器控制或虚构视觉证据。源码未实现时不先把条目标完成。
- **7-B｜Codex**：ADR/架构/README 与实际源码一致；清楚写明无月亮取消、无太阳招募/关系组合/存档/外部概率实现，日常性能未量化。
