依据：[高层计划](earth-high-level-plan.md)、[V1 玩法计划](earth-v1-plan.md)、[开发交接](prd-earth-handoff.md)、[验证指南](testing.md)。本文将 V1 拆成可实施、可验证的步骤；不表示功能、接口协调或玩法 QA 已完成，也不是一次已完成的正式工程审阅。

当前实施状态：V1代码与非浏览器QA已完成，用户本次已明确确认手动浏览器QA通过。历史门槛与逐步结果见 [V1 QA 记录](earth-v1-qa-results.md)。用户已确认此前移动基线通过；新增浏览器体验仍待用户检查。以下是执行规范，不能把各项要求本身当作测试结果。

## QA 分工（按用户最新要求修订）

本轮由 Codex 运行不需要浏览器控制的检查：代码逻辑、模块接口、Node 单元/集成测试、静态服务与构建脚本、格式/lint/文档链接和原件完整性。浏览器中的键鼠操作、画面、声音与实际流畅度由用户手动检查；具体操作与预期见 [用户浏览器检查单](earth-v1-manual-qa.md)。

Codex 不启动或控制浏览器、不运行 Playwright/E2E、不为本轮下载浏览器，也不新增浏览器自动化用例或仅为 E2E 添加的运行时诊断。已有 E2E 文件、断言和 CI 保留；本轮交付写明“按用户要求未运行”，不当作通过。这是用户对本轮 QA 的明确调整，优先于仓库默认要求每次行为改动运行 E2E 的规则；不表示远端 CI 的浏览器任务已取消。

每步分别报告 **Codex 自动/代码检查** 与 **用户手动检查**。用户尚未检查时记“待用户检查”，不伪造 Pass，也不因未完成眼检而停止后续独立的逻辑实现。功能可标“代码就绪，待手验”；完整体验验收需相关用户检查通过。精确数值、相位、对象身份、API 条件由代码测试负责，用户无需用肉眼测量这些值。

## 1. 目标与规划默认值

玩家按 4 成为 Earth，靠近现有月亮后按 E 邀请；原月亮立即进入安全轨道并随 Earth 移动。切换世界后返回仍保留关系，刷新恢复初始状态。

以下沿用上位计划的建议值，作为本文的实施假设。步骤 0 记录共享协作方接受的实际契约；若需更改，先同步参数与验收。本轮用户已明确授权执行全部步骤；接口按 ADR 0002 接受为本地实现契约，不虚构其他贡献者的确认或评审。

| 项目     | 本计划默认值                                                                             |
| -------- | ---------------------------------------------------------------------------------------- |
| 主动邀请 | 不要求先随机触发月亮对白                                                                 |
| 邀请距离 | Earth 与 Moon 中心三维距离 `<= 75`                                                       |
| 状态     | `available → orbiting`；一位伙伴、不可解散                                               |
| 入轨     | 同一个 Moon Mesh 立即安全入轨，不增加过渡状态                                            |
| 轨道     | X/Z 平面半径 `48`，相对高度 `5`，角速度 `0.18 rad/游戏秒`                                |
| 暂停     | Earth 非活动、欢迎、帮助或转场时，月亮相位不推进                                         |
| 减弱动态 | 遵循现有启动时读取的系统偏好；固定相对偏移随行，不持续公转；运行时切换偏好不在本次承诺内 |
| 持久性   | 仅页面内缓存，不写 localStorage 或远端                                                   |
| 内容     | 保留月亮和有环星球的对象与 `talkers`；不改共享随机对白策略                               |

补充授权（本轮用户反馈）：Earth 移动速度由 `19` 提高到 `38` 场景单位/游戏秒，采用固定更快速度；草 `1.65`、人 `7`、岛 `15` 保持不变，不新增惯性或加速度。Earth 仍受半径 `200` 的原边界约束。后续靠近月亮、动作即时复核及轨道跟随 QA 均以此速度执行。此前文档中的“V1 不修改速度”约束由本次用户要求明确修订。

范围外：太阳、新行星、引力、碰撞、平滑入轨、多个伙伴、取消结伴、刷新存档、新声音、外部素材、通用实体框架、相遇概率配置、全局动画无障碍重写和部署。

| `tests/unit/earth-moon.test.mjs`（新增） | 边界、两态转换、幂等、轨道及暂停的逻辑回归                                              |
| `docs/earth-v1-manual-qa.md`             | 用户执行的浏览器操作、预期结果和反馈方式                                                |

保留现有冒烟测试但本轮不运行、不扩写；不默认修改其他世界、共享渲染工具、引擎、原型、依赖、构建或 CI。公共契约确定后补充一份 ADR，并更新架构/玩法说明；这两项文档属于交付范围，不是额外框架建设。

建议使用三个可选回调，最终签名在步骤 0 确认：

| 建议入口                          | 输入与结果                                                           |
| --------------------------------- | -------------------------------------------------------------------- |
| `world.getPrimaryAction(context)` | 读取当前资格，返回 `{ label }` 或 `null`；无副作用                   |
| `world.onPrimaryAction(context)`  | 再次验证资格；仅成功转换时返回反馈文本，否则返回 `null`              |
| `world.update(context)`           | 使用共享 `dt`、允许模拟标志及减弱动态偏好，更新 Moon；不创建动画循环 |

`context` 至少明确 `dt`（更新时）、`canInteract`、`canSimulate` 和 `reducedMotion`。位置直接读所属世界的 `w.position`；控制器只调用活动世界。暂停时仍可调用更新入口，但必须不推进相位。非活动世界不调用。未提供回调的世界沿用旧行为，草仍调用既有 `recruit()`。

```text
共享按键状态 → 移动并夹取 w.position
             → 活动世界 update（Moon 读最新 w.position）
             → placeCamera（同步 avatar 与镜头）
             → 主动作提示刷新 + 原有相遇检测
             → render

E keydown → 检查 started/help/switching/repeat
          → 草：原 recruit()
          → Earth：重新检查资格 → 一次状态转换 → 一次反馈
          → 人/岛：无主动作
```

## 3. 实施顺序与逐步 QA

步骤编号用于本文件追踪，不代表已创建 Issue。每步必须记录 Pass / Fail / Blocked、命令或操作路径、证据和剩余问题；未执行不能记 Pass。后续依赖步骤不得把前置逻辑失败当作通过；“待用户检查”单独记录，不阻止不依赖其结论的代码工作。步骤 1–5 可作为一个配套功能改动交付，禁止单独合并永远不会被调用的回调。

### 步骤 0：锁定范围、共享契约与基线

实施：核对 HEAD 和未提交差异；确认本轮做月亮结伴；由共享控制器/UI 与 Earth 协作方记录上述回调或等价方案、调用顺序、提示归属及相遇策略边界。按决策模板记录实际选择，状态在接受前保持“提议”。关联现有 `PERF-01`、`A11Y-02`、`DESIGN-01`，不凭空创建负责人。

Codex 记录版本、Node 环境、共享接口提议并运行非浏览器基线。用户按检查单 M0 记录实际设备并试玩当前 Earth 和草层；无需先提交三次 60 秒性能采样才能开始代码工作。正式帧时间/heap 测量转为条件性专项检查，见步骤 8。

QA 门槛：

- **0-A**：实际接口、分工和本文件默认行为有可追溯记录；外部相遇配置若尚未接入，明确当前基线为 Moon 存在且可邀请，不伪造概率接口。
- **0-B｜Codex**：Node 为 `>=22.13 <23`，`npm run check` 有真实基线结果；不运行 `test:e2e`，明确标记为用户要求跳过。既有非浏览器检查失败须记录并处理。
- **0-C｜用户 M0**：记录设备/浏览器并检查现有 Earth 移动、镜头和草 E 基线；结果待用户反馈。三次性能采样不是日常 QA 或实施前置条件；未测量不宣称性能达标。

### 步骤 1：建立 Moon 局部状态与可测试逻辑

实施：在 `space.js` 保留并引用当前 `moon`；保留它挂在 `w.scene` 下及原 `talkers.object`。将两态与必要参数放在 Earth 自身，使用专用模块处理计算，不放入草的 `followers/recruitables`。逻辑模块接受数值、位置和允许动作标志，不操作 DOM、音频或渲染器。

QA 门槛：

- **1-A｜单测**：初始 `available`；邀请距离为三维距离。在 `74.999`、`75`、`75.001` 分别允许、允许、拒绝；覆盖含 Y 偏移的边界，防止误用水平距离。
- **1-B｜单测**：Moon 不存在或明确不可邀请时，查询和执行均安全返回无动作；状态不变，不自动补造月亮。
- **1-C｜对象集成检查**：记录实际 Moon 与有环星球的引用，确认前后还是同一对象、各一份；`talkers` 仍指向它们。此项检查在接好步骤 5 后复验，不以纯逻辑 mock 代替实际场景检查。
- **1-D｜静态检查**：新增状态没有进入草数组，没有第二个随机源调度器、动画循环、监听或音频上下文。

### 步骤 2：接入安全的共享动作与更新路由

实施：在共享键盘入口按活动世界分派 E；统一检查已开始、帮助关闭、未转场及 `!e.repeat`。E 无论成功与否都不跨场景回退到草招募。将活动世界更新放在移动/边界夹取之后、镜头与相遇检测之前，使用同一个最大 `0.05` 秒的 dt。保留原 Earth 自转一处，不在回调重复更新它。

QA 门槛：

- **2-A｜Codex + 用户 M1/M3/M7**：非浏览器路由测试验证 E 只调用活动场景处理器，草计数不受 Earth 影响。用户实际按 E 验证草招募、人/岛无副作用和 Earth 邀请。
- **2-B｜Codex + 用户 M2/M3**：路由测试传入未开始/帮助/转场/重复按键状态，验证未调用动作；用户用实际键盘复核阻挡、长按和连按。不靠直接伪造成功处理结果通过。
- **2-C｜时序验证**：同一帧移动和更新后，Moon 使用新的 `w.position`；不能落后一帧。已有单个 RAF、监听数量不增加，Earth 自转速率保持原 `0.018 rad/游戏秒`。
- **2-D｜Codex + 用户 M7**：非浏览器接口测试覆盖无回调世界的安全回退；源码检查所有调用方；用户验证人/岛正常移动和切换，无错误或卡住。

### 步骤 3：显示正确且及时失效的邀请提示

实施：复用 `#invite` 容器，通过 `textContent` 填入当前世界动作文案；草文案保持原样。Earth 资格成立时显示“E 邀请月亮同行”，其他情况隐藏。提示每帧做轻量资格查询，DOM 仅在文本/可见性变化时写入；帮助打开、转场开始立即隐藏，避免沿用原每 12 帧相遇采样造成过时提示。提示查询和动作执行复用同一个资格规则。

QA 门槛：

- **3-A｜Codex + 用户 M1**：单测验证资格查询在距离边界返回动作/null；代码检查每帧查询与 DOM 仅按变化写入。用户用 WASD 验证靠近显示、离开及时隐藏；不要求肉眼分辨一帧或精确 75 单位。
- **3-B｜用户 M2/M4**：帮助打开、切离 Earth 后无遗留提示；返回未结伴 Earth 时按当前距离恢复；草提示及同行计数仍正确。
- **3-C｜用户 M6**：960×640 与演示视口下文案可读、未裁切、不被底部尺度按钮遮挡；键盘用户能看到 E 操作说明；不新增无标签控件或抢夺焦点。

### 步骤 4：执行一次邀请与安全入轨

实施：E 执行时重新读取位置和全部资格；成功才将 `available` 改为 `orbiting`，放置原 Moon 并返回一次“月亮，与你同行。”反馈。先计算水平偏移 `dx = moon.x - earth.x`、`dz = moon.z - earth.z`，再使用显式分支 `dx === 0 && dz === 0 ? 0 : Math.atan2(dz, dx)`；这定义了“没有水平朝向时选 +X”为产品行为，并统一正负零输入，不是为了防止 `atan2(0, 0)` 抛错（它不会）。不要因重复 E 重新初始化相位。

QA 门槛：

- **4-A｜单测**：提示查询后把 Earth 移出范围，再执行必须失败；未开始、帮助、转场、已结伴也必须失败。拒绝时不移动 Moon、不返回成功反馈。
- **4-B｜单测**：有效邀请恰好转换一次；连续执行 20 次只有第一次返回成功，后续状态与相位不被重置；零水平偏移（含只有高度差）、完全重叠和不同象限均得到有限坐标与相位；零水平偏移及正负零组合必须选相位 `0`，入轨到 Earth 的 +X 方向。测试注释说明这是显式分支的方向选择回归，不是测试 JS 的 `Math.atan2(+0, +0) === 0` 语言保证。
- **4-C｜Codex + 用户 M3**：场景模块集成验证状态转换前后 Moon 身份和两条原天体记录不变；用户通过 E 实际邀请，确认提示消失和一次成功反馈。
- **4-D｜用户 M3**：按住及连按 E 后草同行数不变，不重复反馈；不要求或强制先播放月亮对白。

### 步骤 5：运行轨道与移动跟随

实施：允许模拟且未减弱动态时，`theta = (theta + 0.18 * dt) % (2 * Math.PI)`。用玩家最新中心计算 `moon = earth + (48*cos(theta), 5, 48*sin(theta))`。原 Moon 保持 scene 子节点，不跟随 globe 自转；每帧复用已有状态，不新建几何、材质、数组或 Vector3。

QA 门槛：

- **5-A｜单测**：稳定轨道水平半径 `48`、高度偏移 `5`，容差 `1e-6`；三维中心距离应等于 `Math.hypot(48, 5) = sqrt(48² + 5²) ≈ 48.26`（同样容差），减去大气半径与 Moon 半径之和 `24.1 + 9 = 33.1` 后净间隙约 `15.16`。断言使用推导表达式而非硬编码 `48.26`，测试旁注释区分水平半径与三维中心距离，避免将后者“简化”为 `48`。
- **5-B｜单测**：按 `0.05` 秒步长推进，累计相位符合 `0.18 * elapsed`，按圆周等价比较；覆盖 dt 为 0、长时间推进及相位绕回，位置始终有限。
- **5-C｜Codex + 用户 M3**：非浏览器模块集成依次设置真实世界位置并调用真实更新入口，覆盖静止、两轴、对角线和边界位置，断言 Moon 相对最新中心的半径/高度；用户实际移动观察随行。不直接将浏览器内状态设为成功。
- **5-D｜用户 M3/M6**：观察至少一圈，运动连续，无附加随 Earth 自转的旋转、闪烁或稳定轨道穿插；复验 1-C 的真实对象身份与数量。

### 步骤 6：保留会话并实现暂停/减弱动态语义

实施：使用已有世界缓存保留状态和相位，禁止重建或在重新进入时初始化。Moon 相位只按允许模拟的 dt 累积，不用全局 time 推导。欢迎、帮助和转场暂停；非活动不更新。启动时减弱动态模式下相位固定，但 Earth 移动时继续更新相对位置。

QA 门槛：

- **6-A｜Codex + 用户 M4**：模块集成验证缓存对象复用、非活动不更新相位、返回仅推进允许的 dt；用户邀请后离开约 10 秒再返回，确认关系仍在且没有明显跳位。精确相位由代码测试负责。
- **6-B｜Codex + 用户 M2/M4**：模块/API 测试验证帮助和转场 context 禁止邀请、相位冻结及恢复无补算；用户打开帮助约 5 秒、切换时尝试 E，观察暂停与恢复。不重写共享时钟或旧动画。
- **6-C｜Codex + 用户 M5**：在同一逻辑/模块测试中保持 `reducedMotion=true`，沿 X/Z 与对角线改变 Earth 位置并调用真实 update，分别断言 Earth 有位移、相位不变、Moon 世界坐标重定位且相对偏移三分量不变（容差 `1e-6`）。用户在系统开启减弱动态后刷新，实际移动确认“随行但不公转”，无需读取相位。
- **6-D｜Codex + 用户 M4**：非浏览器工厂集成验证新会话初始化为原位置与 available；用户刷新确认回到初始状态，并能重新完成邀请。

### 步骤 7：验证对白、反馈和镜头构图

实施：保留现有 Moon/有环星球的几何、灯光和对白。默认只调整提示及确有证据的问题，不附带视觉翻新。邀请反馈复用现有 toast；其 4 游戏秒寿命沿用当前时钟。月亮结伴后仍参加原共享对白候选选择，不追加独立冷却或去重规则。

QA 门槛：

- **7-A｜用户 M6**：观察邀请前/后、默认距离 120、最近 66、最远 288，以及 Moon 绕到背后的画面；仅发现问题或需要对照时保存截图。Earth 主体、提示和反馈可理解，无裁切；自然遮挡和最近镜头未完全容纳 Moon 可接受。
- **7-B｜Codex + 用户 M8**：实际场景两条天体记录继续有效，移动 Moon 后距离检测读到正确世界坐标。非浏览器可控候选测试验证两者都可被共享系统选择；真实试玩记录对白结果，不要求随机选择在固定秒数内必定选中 Moon。
- **7-C｜用户 M9（可选体验记录）**：至少一名未被告知路线的试玩者，从按 4 的转场结束计时，仅凭屏幕说明在约 30 个真实秒内完成邀请；记录游戏时间、路径和设备。若失败，记录原因并调整局部可读性后复测，不强制对白、不自动邀请或修改全局概率。
- **7-D｜Codex + 用户 M7/M8**：草文案不被 Earth 覆盖；Moon 原对白及来源说明不变；无新资源请求、错误日志或声音上下文。

### 步骤 8：四层回归、资源与真实设备性能

实施：Codex 运行 `npm run check` 及不创建浏览器/WebGLRenderer 的 Earth 单元/模块接口测试；用户按 M0–M8 完成一轮手动操作。M9 发现性和 M10 性能分析作为额外取证，不占用日常实现循环。

QA 门槛：

- **8-A｜Codex**：`npm run check` 及 Earth 非浏览器测试通过；不跳过有效单元用例、不放宽断言/lint。检查本地资源引用、监听/RAF/AudioContext 创建路径，标明静态检查不能证明真实浏览器无网络请求或运行时错误。Playwright/E2E 按用户要求不运行，保留已有文件和 CI。
- **8-B｜用户 M7/M8**：草 E 招募及 12 株上限、跟随与切换保留；四层按钮/快捷键、移动、拖动/缩放、帮助/Escape 焦点返回、声音开关、失焦释放按键均通过；控制台无红色错误、Network 无新增远程资源。
- **8-C｜Codex + 用户 M7**：模块集成检查缓存返回同一对象、邀请/更新不新建 Moon 和有环星球；静态检查无循环/重复监听/音频上下文创建路径。用户完整往返四层 10 次，确认没有可见复制、越来越卡或声音叠加。此结果不等于 GPU/heap 无泄漏证明；精确资源计数与 GC 样本属于 M10 专项。
- **8-D｜用户 M7；量化部分条件性 M10**：日常检查在实际设备探索 2–3 分钟，报告是否有明显停顿或交互迟滞。原建议阈值（中位帧时间 `<=33.3ms`、相对基线中位/P95 增幅 `<=10%`）保留为专项候选，只有用户选择量化评估并确认设备/口径后才生效；未执行写“未量化”，不能写“30 FPS 达标”。不阻挡后续独立的逻辑工作。

可选专项配置说明：正常性能采样与GC内存诊断分会话；不要假定普通页面有window.gc。无法可靠强制GC是常见的未验证情形，记录即可，不用诊断会话帧率替代正常性能基线，也不要求Codex控制浏览器。

条件性专项 M10 的 heap 协议（仅用户选择分析内存或出现退化时执行，Codex 不控制浏览器）：

1. 用户预热四层，回到相同 Earth 位置/镜头；关闭可能保留对象引用的控制台求值，等待 2 个真实秒。
2. DevTools 允许时，在 Memory 面板点 Collect garbage，等待 2 个 RAF 后测量 heap；未切换先重复 3 次，记录参考波动。不能可靠触发/读取时记未验证，不要求为日常眼检配置 CDP。
3. 每次完整往返后采用相同位置/等待/GC/采样顺序，保存 10 个往返后样本（另保留 3 个参考样本），注明 GC 是否执行及可取得的 geometry/texture 等计数。
4. Codex 可离线分析用户提供的数字/导出文件，比较第 1/10 次及前 3/后 3 次中位数。超出参考波动的增长是调查信号；需再次同样测量并查看 heap snapshot 保留路径，不能只凭两个端点认定泄漏。
5. 确认持续新增的不应保留对象/模型/监听可判 Fail；稳定曲线只能报告本路径/窗口未发现增长。没有工具或样本则该专项为未验证，不妨碍报告已通过的逻辑和操作项。

## 4. 无浏览器测试与用户检查的边界

```text
Codex：Node / 静态检查，不启动浏览器
  ├─ 距离/缺失/阻挡/重复调用 → 1、2、4
  ├─ 两态/相位/几何/最新位置/暂停/减弱动态 → 4、5、6
  ├─ 实际场景对象/缓存/talkers/API 签名与调用顺序 → 1、2、6、7
  └─ HTTP 服务/构建/文档链接/格式/lint → 0、8、9

用户：实际浏览器操作，详见独立检查单
  ├─ 当前 Earth 提速 → M0
  ├─ 提示/邀请/阻挡/跟随/切换/刷新/减弱动态 → M1–M5
  ├─ 构图/四层操作/声音/对白 → M6–M8
  └─ 发现性记录/量化性能与 heap（可选） → M9–M10
```

测试调用真实业务逻辑与实际模块入口，避免复制实现或硬编码成功。模块对象检查可使用本地 Three.js 对象，但不创建 WebGLRenderer；若场景工厂依赖 canvas，隔离真实的对象装配/业务部分供 Node 测试，最小化拆分，不以完整浏览器模拟替代浏览器、不为测试造第二套玩法。

输入路由与 UI 阻挡可用小型回调 spy / 必要 DOM stub 测调用契约；它们只证明逻辑分派，实际键盘焦点、DOM 呈现和事件接线必须由用户复核。只有确实需要时才从现有控制器提取小函数，不提前建设测试框架。

精确的轨道数值、对象身份、幂等与缓存由 Codex 测试，用户不需在 DevTools 读取私有世界状态。本轮不为 E2E 新增 canvas 诊断、可写全局状态、测试传送按钮或额外浏览器依赖。

每次交付附非浏览器检查结果、受影响的手验编号、启动命令和预期变化。用户尚未执行的编号保持待验；用户给出失败路径后，Codex 调查代码并回归非浏览器测试，再给出最短复测步骤。
