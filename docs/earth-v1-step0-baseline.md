## 环境恢复与提速回归记录

- `npx playwright install chromium` 已完成，安装项目所需 Chromium/headless shell v1248 与 FFmpeg。下载中曾发生连接中断，安装器重试后完成；未更改 npm 依赖或锁文件。
- 在 headless shell 尚未就绪时尝试 `npm run test:e2e -- --headed`：失败，首段草移动断言未检测到位移；失败快照活动世界为 3，与该步骤预期不符。此尝试不算通过，也没有据此修改游戏或放宽断言。没有足够证据归因于具体环境或外部输入。
- 提速后的 `npm run check`：Pass（格式、lint、3 项单元/仓库测试、构建）。gstack 曾自动生成根目录 `.gstack/` 诊断导致格式检查失败，已将该次工具诊断移入忽略的 `.local/gstack-step0/`，保持原检查规则与 `.gitignore` 不变，重新检查通过。
- 最终使用项目原配置的 `npm run test:e2e`：**Pass，1 项 Chromium 冒烟，约 2.4 分钟**。测试增加的真实输入位移断言全部通过：人 7、岛 15、Earth 38、草 1.65；Earth 对角线归一化、松键停止与半径 200 边界均通过，没有直接写入玩家状态。原有进入、草招募/对白、切换、声音开关、帮助、刷新及无外部资源断言也全部通过。这是提速后工作区的回归结果，不回填为提速前首次基线通过。
- 真实设备帧率、视觉构图、长期内存和人工听感仍未验证；软件 WebGL 测试即使通过也不代表这些项目完成。

## QA 分工调整与当前下一步

用户在上述历史验证完成后明确要求：跳过所有需要浏览器控制的 Codex 测试，由用户自己做视觉和控制检查，Codex 负责代码逻辑、模块/API 与脚本测试。因此上述已执行的 2.4 分钟 E2E 结果只作历史记录；后续本轮不重跑、不下载浏览器、不添加浏览器自动化或专用运行时诊断，保留已有测试与 CI。

当前步骤 0 的范围/自动基线记录已具备；共享契约仍为提议，实际设备体验标“待用户检查 M0/M7”。性能/heap 数字改为 M10 条件性专项，未做记“未量化”，不再把三次 60 秒浏览器测量作为开始后续独立逻辑工作的门槛。不能将用户尚未操作记为 Pass，也不因待眼检停止独立代码准备。

用户当前按 [手动检查单](earth-v1-manual-qa.md) M0 验证 Earth 提速，以及 M7 中已有控制即可。月亮邀请尚未实现，相关检查在代码交付时再列出。Codex 后续执行 `npm run check` 与 Node 单元/模块集成测试，交付时报告代码结果及需要用户复测的编号。
