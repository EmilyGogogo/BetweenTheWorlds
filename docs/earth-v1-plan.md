## 1. V1 的玩家体验

```text
按 4 进入 Earth → 注意到已有月亮 → 靠近
              → 看见“E 邀请月亮同行”
              → 按一次 E → 月亮进入安全轨道并随 Earth 移动
              → 离开 Earth 再返回 → 仍在同行
```

玩家可以不邀请，继续漫游。没有任务完成弹窗、分数或强制解锁。月亮原有的短句继续通过共享相遇系统触发。

**建议默认行为：**邀请由距离和月亮当前状态决定，不以随机播放过某句对白为前提。原提案中的“先听月亮说话再按 E”作为可能的体验顺序，不作为必须等待的状态机条件。若项目方要求对白先行，需要共享相遇结果通知，属于额外接入依赖，不能在 Earth 内偷偷复制对白调度。

## 2. 当前可复用的代码与约束

**场景已经有 Earth、月亮、有环星球三个主要天体。V1 不新增天体，而是升级已有月亮，并完整保留有环星球。**月亮是卫星；有环星球尚未正式命名为土星。当前没有可见太阳模型，`w.sun` 只是灯光。

| 项目       | 当前事实                                                        | V1 处理                                             |
| ---------- | --------------------------------------------------------------- | --------------------------------------------------- |
| Earth      | `w.avatar` 根节点、半径 23 的 `w.globe`、半径 24.1 的大气       | 保留引用与主控制器依赖                              |
| 月亮       | 已有 Mesh，半径 9，初始位置 `(80,5,-65)`，挂在 `w.scene`        | 升级现有对象，不再创建第二个月亮                    |
| 月亮对白   | `w.talkers` 中范围 75 的记录                                    | 保持 object 引用与内容有效                          |
| 有环星球   | 既有模型及范围 290 的对白                                       | 保留；不要为演示月亮而擅自移除或修改共享选择策略    |
| Earth 移动 | 基线速度 19；本轮用户授权提高为 38，X/Z 平面、半径 200 边界不变 | 仅 Earth 提速，不增加碰撞、受力或其他层速度变化     |

| 动画       | 无 `world.update` 回调                                          | 接入后才能运行轨道，不另开动画循环                  |

## 3. 范围

实现时直接复用 `makeSpaceScene()` 中现有的 `moon` Mesh 及其 `talkers` 记录。`p`、`gas`、`ring` 共同构成已有有环星球，不能误当成三个需要重新创建或替换的天体。邀请、返回场景或增加对象引用都不应再次调用模型创建代码来复制月亮。

### 本次包含

- 月亮接近资格判断、可理解的键盘提示、一次 E 邀请。
- 月亮进入简化圆形轨道并与移动的 Earth 同行。
- 简短视觉/文字反馈；重复操作不产生新对象或重置关系。
- 离开/返回 Earth 的会话状态，以及减弱动态效果处理。
- 必要的共享输入、提示与主循环接入，单独协调并审阅。
- Earth 专项验证及其他三层关键回归。

### 本次排除

太阳、新行星、真实引力、碰撞、弹弓、连锁事件、多个伙伴、取消结伴、刷新后保存、新声音系统、外部素材加载、统一实体框架，以及相遇概率参数的实现。

轨道期间保证 Earth 与 Moon 的中心距离足够，不能等同于新增自由移动碰撞系统。结伴前玩家仍可能像当前版本一样移入物体；V1 不承诺解决整个场景的碰撞。

## 4. 前置接入门槛

Earth 负责人不应在前置接入未确认时，修改 `main.js` 来自行扩张范围。可先完成已有代码阅读、构图基线和局部状态设计。

| 接入能力       | 负责方                               | 最低要求                                                                            |
| -------------- | ------------------------------------ | ----------------------------------------------------------------------------------- |
| 活动世界主动作 | 共享控制器负责人，Earth 配合         | E 按当前场景分派；草仍走原招募；忽略重复按键；欢迎、帮助、转场期间不执行 Earth 动作 |
| 互动提示       | 共享 UI/控制器负责人，Earth 提供内容 | 能显示 Earth 的 E 提示和反馈；切换或失效时隐藏；不破坏草层提示与计数                |
| 逐帧更新       | 共享主循环负责人，Earth 提供更新逻辑 | 只在活动 Earth 且允许模拟时调用，使用统一 dt；不重复注册或另启循环                  |
| 相遇策略边界   | 相遇系统负责人                       | 明确外部参数控制什么，以及主动动作是否独立于随机对白                                |

建议的数据流：

```text
共享输入更新 w.position
    → Earth 更新月亮位置
    → 共享镜头放置
    → 共享相遇检测与提示刷新
    → render
```

使用 `w.position` 作为玩家位置来源，避免在 `placeCamera()` 前读到上一帧的 `w.avatar.position`。UI 更新可以使用合适的采样频率，但动作执行时必须重新检查资格。

可讨论的最小接口职责如下，**命名与签名需双方确认后才成为代码契约**：

| 建议入口                          | 职责                                                            |
| --------------------------------- | --------------------------------------------------------------- |
| `world.update(context)`           | 用共享 dt 更新本场景的轨道；context 明确活动/暂停与减弱动态语义 |
| `world.getPrimaryAction(context)` | 返回当前可用动作的说明，或无动作；供控制器呈现提示              |
| `world.onPrimaryAction(context)`  | 在重新检查距离和状态后，执行一次邀请                            |

共享层可选更小的等价接法，不要求三个函数或一个通用框架。无论选择哪种，需保证没有 callback 的其他世界保持原行为。必要的公共契约按 [决策模板](decisions/template.md) 记录；不能把本计划当成已经通过的 ADR。

## 5. 状态与动作规则

### 5.1 建议的最小状态

```text
available：月亮独立存在，可能满足邀请距离
    -- 有效 E 动作 -->
orbiting：月亮已与 Earth 同行
```

状态可存放在 Earth 世界对象上，例如 `w.earthState.moon`，包含状态和轨道相位即可。该字段目前不存在。不要把月亮塞进草层 `followers/recruitables`，也不需要全项目 State Manager。

### 5.2 资格与提示

- Earth 活动、游戏已开始、帮助关闭、未转场、月亮存在且状态为 `available`。
- 邀请距离建议初值为中心三维距离不超过 `75` 个场景单位；沿用已有范围的量级，但不是相遇概率参数。
- 满足资格时显示“E 邀请月亮同行”；离开范围或被 UI 阻挡时隐藏。
- 按 E 的当时重新读取距离、状态与允许输入条件，不依赖上一次提示结果。
- 状态为 `orbiting` 时不再显示邀请提示；重复 E 不创建物体、不重新初始化轨道，也不把动作传到草层。
- 若世界配置决定月亮不存在或不可邀请，则无提示、无动作。不得用必定生成的额外月亮绕过外部配置。

### 5.3 邀请发生时

建议 V1 立即将现有月亮放到安全轨道起点，并显示一次简短反馈，例如“月亮，与你同行。”保留其对象身份与对白引用。平滑入轨是后续可选打磨，不作为首版额外状态。

用 Earth 指向月亮的当前水平朝向确定初始轨道相位，尽量减少方向跳变；水平偏移为零时显式选相位 `0`（+X 方向，统一正负零），这是方向约定，不是为避免 `Math.atan2(0, 0)` 抛错。即使邀请前发生物体重叠，也应在邀请后进入安全轨道。

此选择是为缩小 V1 范围的建议默认值，需在开始实现前确认；若改成平滑入轨，需要补充过程状态、移动中加入和中途离开场景的验收。

### 5.4 会话与暂停语义

| 事件               | 建议行为                                                       |
| ------------------ | -------------------------------------------------------------- |
| Earth 移动         | 已结伴月亮跟着玩家中心移动，并继续相对公转                     |
| Earth 非活动       | 保留状态和相位，暂停月亮的局部动画                             |
| 欢迎/帮助/转场期间 | 不接受邀请；月亮轨道暂停；共享游戏时钟和其他既有行为不因此重写 |
| 返回 Earth         | 保留结伴和相位，围绕保留的玩家位置恢复                         |
| 刷新页面           | 恢复独立月亮、初始位置和未结伴状态                             |
| 开启减弱动态效果   | 月亮保持固定相对偏移跟随 Earth，停止持续公转                   |

相位用 dt 累积，不直接用全局绝对 time 重算，避免离开或暂停后突然跳到新轨道位置。当前 Earth 自转尚不尊重减弱动态偏好，属于已有共享问题；本次不通过新轨道逻辑默默扩大为所有动画修复。

## 6. 轨道与构图

下列是待试玩的起始参数，不是正式性能或视觉指标：

| 参数         | 建议初值 / 约束                                                                           |
| ------------ | ----------------------------------------------------------------------------------------- |
| 水平轨道半径 | `48` 场景单位                                                                             |
| 相对高度     | `5` 场景单位                                                                              |
| 角速度       | `0.18 rad/游戏秒`，一圈约 35 游戏秒                                                       |
| 参考中心     | `w.position`，不是旋转中的球面纹理或镜头                                                  |
| 轨道平面     | X/Z 平面，不做天文轨道拟合                                                                |
| 非相交约束   | 按实际模型与大气尺寸检查；当前大气半径 24.1 + 月亮半径 9 = 33.1，轨道中心距离应额外留余量 |

继续让 Moon 挂在 `w.scene` 下，用玩家中心加相对轨道偏移更新世界位置即可；不要求重新挂到 `w.globe` 下，以免随 Earth 自转额外旋转。若选用父子轨道节点，应保证世界坐标和 `talkers.object` 引用一致。

在默认镜头距离 120、缩放范围 66–288，以及不同拖动角度检查构图。近距离不要求月亮始终完整入镜，但不能因此失去可理解的邀请提示或把 Earth 主体挤出画面。绕到 Earth 背后被自然遮挡可以接受；V1 不新增穿透标记或强制镜头跟随月亮。

结伴后的月亮继续是共享对白候选。当前没有每对象去重，它仍可能在共享冷却后重复发言；若要改变频率、去重或加入后禁言，交由相遇策略负责人协调，不在 V1 私自更改。

## 10. 开始实现前确认清单

这些是建议默认值与外部依赖，不能写成已经达成的讨论结论：

- [ ] 本轮以月亮结伴作为增量；视觉最低可读性同时纳入，不追加完整视觉翻新。
- [ ] 共享负责人接受主动作、提示、更新能力的分工，并确定实际签名和调用顺序。
- [ ] 主动邀请不以随机对白为前提；外部相遇参数对对象存在/动作资格的影响明确。
- [ ] V1 采用立即安全入轨、仅一个伙伴、不可解散，不增加平滑入轨状态。
