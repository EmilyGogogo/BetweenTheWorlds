# 验证与试玩

## 本轮 Earth V1 的执行分工

按用户最新要求，Codex 只运行不需要浏览器的代码逻辑、模块/API、Node 单元/集成、服务脚本、格式/lint/链接与构建检查，默认执行 `npm run check`。键鼠控制、画面、声音与实际流畅度由用户按 [Earth 手动检查单](earth-v1-manual-qa.md) 操作。

本轮 Codex 不启动/控制浏览器、不运行 `npm run test:e2e`、不下载浏览器，也不新增浏览器自动化用例。现有 E2E 文件、有效断言和 CI 保留；下方浏览器命令与覆盖说明保留作仓库参考，不是本轮每次本地修改的要求。用户这项明确调整优先于仓库默认 E2E 执行规则；交付标记“E2E 按用户要求未运行”，用户结果标“待用户检查”，均不写成通过。

精确逻辑由 Codex 测试，实际 DOM 事件接线、焦点、渲染与听感依赖用户检查。量化帧率与 heap 分析为条件性专项，不是日常眼检门槛。

## 自动检查

使用 Node.js 22.13 或更高的 22.x 版本。旧版本需要先升级；`.nvmrc` 指向 22.x，CI 使用该系列的最新版本。

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
npm run test:e2e:smoke
```

Linux 首次安装浏览器可使用 `npx playwright install --with-deps chromium` 补齐系统依赖。`npm run check` 依次检查格式、ESLint、单元与仓库完整性，再生成 `dist/`。浏览器测试直接使用这个发布目录，运行前需要已执行 `npm run build`。

单元与仓库检查覆盖原始附件/第三方文件哈希、文档本地链接、静态服务的资源类型及目录访问边界。浏览器冒烟在 Chromium 中创建真实 WebGL 场景，覆盖进入、移动、同行、对白显示、四层切换、人层 glTF 模型实际加载完成、帮助、声音开关、会话状态保留与刷新重置，并阻止外部资源请求。人层冒烟覆盖第一人称、观察笔记随人物变化、人物面板键盘操作、望远镜、视角切换与跨层保留。动物行为（逃跑、缩壳、群体报警、风向、草药吸引、惊吓、先注视再逃、母象警告后领幼崽离开、家畜跟随与凑近、鸟群起飞后落回、栖在灌木上不离开）、其他人的日程与反应（日程循环、走近时只招呼一次、放轻脚步不吵醒睡着的人、专心画画时不理人、幼儿跟着母亲并躲到她身后、孩子好奇凑近）与观察规则由 `tests/unit/` 中的纯逻辑测试覆盖，动画观感需人工确认。

冒烟测试在页面加载前暂停 Playwright 时钟，按 50 毫秒一帧推进真实游戏逻辑，对应游戏每帧允许的最大时间步长。移动距离与对白冷却按游戏时间验证，避免软件 WebGL 的低帧率导致实际等待超时；切换期间输入被锁定，直接推进两段淡入淡出定时器并渲染场景。测试不会替换渲染器、设置玩家位置或伪造对白。失败日志包含位置、当前尺度、对白和焦点状态，便于排查 CI 环境差异。

本轮移动回归还通过实际按键与位置诊断验证每游戏秒位移：草 `1.65`、人层默认阿禾 `6.3`（基础速度 `7` × 人物倍率 `0.9`）、岛 `25`、Earth `38`；Earth 使用对角线输入检查归一化，并检查松键停止及半径 `200` 的边界。位置诊断每 30 帧采样，测试在读取前推进空闲帧以刷新诊断，不通过直接写入玩家位置伪造结果。位移断言按尺度拆在 `tests/e2e/world-movement.spec.js` 的四个独立用例中，保留对角线、松键、边界与人层 Shift 慢走检查，避免把四层位移叠加到完整探索用例后触及本地 240 秒时限；不增加超时预算或删减断言。

PR #9 发布回归：角色加载状态 `data-avatar` 每帧同步，避免切入人层后仍保留上一尺度的 `built-in`；位置等诊断数据仍每 30 帧更新。冒烟测试先在暂停时钟下验证人层已报告 `loading` 或 `ready`，再推进帧等待真实 glTF 模型加载到 `ready`，不依赖 CI 的渲染速度。人工复查时从草层按 2 进入人层，按 V 查看第三人称角色，再切到岛层并返回人层，确认角色可见且可移动；控制台不应出现模型加载错误。

冒烟测试的耗时由软件 WebGL 的栅格速度决定，不由游戏逻辑决定：本地强制 swiftshader 约需 190 秒，核心数更少的 CI 机器更慢。因此单用例预算在 CI 下为 600 秒，本地保持 240 秒，`ci.yml` 的 `timeout-minutes` 必须高于该预算加上安装与构建时间。调整预算不改变任何断言；若耗时持续接近上限，应减少场景的渲染开销或拆分用例，而不是继续抬高预算。

## CI 的浏览器检查分层

完整的浏览器用例共 13 个，在本机 Chrome 加软件 WebGL 下串行约 18 分钟，CI 上也要 13 分钟以上，且对 runner 速度敏感，PR 上的偶发超时会掩盖真实问题。因此 `ci.yml` 的 `Browser smoke` job 分两层：

- **PR**：运行 `npm run test:e2e:smoke`，即 `--grep-invert @full`，共 4 个用例：`pages`（子路径加载）、`human-layer`、完整探索（四层切换、人层 glTF 加载、会话状态、无外部请求）和太阳涟漪（一次 R 换身）。本机约 3 分钟。
- **push 到 main 与手动触发（`workflow_dispatch`）**：运行全部用例 `npm run test:e2e`。需要在某个 PR 分支上跑全量时，可在 Actions 页面对该分支手动触发 CI。

标题中带 `@full` 的用例属于重用例，共 9 个：`world-movement` 四个尺度的位移、`human-embodiment` 三个、海鸥变鱼，以及四层 R 换身。新增浏览器用例时，除非它是必须在每个 PR 上拦住的主流程，否则请在标题加 `@full`。

这降低了 PR 上的浏览器覆盖：重用例的回归会在合并到 main 之后才暴露。位移速度、R 换身等数值逻辑另有 `tests/unit/` 覆盖。本地改变游戏行为、模块接线或发布输出时，仍按 `AGENTS.md` 运行完整的 `npm run test:e2e`。job 名称保持 `Browser smoke` 不变，避免影响可能已配置的必需检查。

CI 中失败的浏览器用例会保留 Playwright trace（`playwright.config.js` 的 `trace`，仅在设置了 `CI` 时启用，不含截图，以免增加软件 WebGL 的开销）。`ci.yml` 在 browser job 失败时把 `test-results/` 上传为 `playwright-traces` artifact，保留 14 天。排查时从该次运行页面下载，解压后用 `npx playwright show-trace <路径>/trace.zip` 查看操作序列、DOM 快照、控制台与网络。本地运行不生成 trace；需要时可临时加 `--trace=retain-on-failure`。

当前自动化不代表所有边界已覆盖：12 株上限、对白的完整冷却时序、镜头拖动/缩放仍需人工验证。浏览器测试使用软件 WebGL，界面视口为 960 × 640 CSS 像素，像素比为 0.5，以减少 CI 的栅格计算量；它不是画质、真实声卡或性能验收，不进行截图比对。未安装 Chromium 时应明确记录未执行，不能当作通过。

`pages.spec.js` 将真实 `dist/` 挂载在 `/BetweenTheWorlds/` 下，验证样式、入口、Three.js 与游戏初始化均可加载，并拦截子路径之外和外部站点的资源请求。对应 `RELEASE-01`；首次远端发布后，还需按 [发布指南](deployment.md) 检查线上版本、资源请求与本节人工清单，本地通过不代表 GitHub Pages 已启用。

本轮新增 Node 用例覆盖 Earth 邀请距离/资格/幂等、初始方向、长时间轨道、最新中心、暂停/减弱动态、实际工厂对象与资源身份、新会话重置，以及共享路由/提示 DOM 适配；纹理绘制使用 Node stub，不启动 WebGL，不代表画质或实际事件接线通过。具体结果见 [V1 QA 记录](earth-v1-qa-results.md)。

## 人工回归清单

记录提交版本、设备、浏览器、窗口大小、系统减弱动态效果设置及执行结果。

- 进入与错误反馈：正常加载可进入；禁用硬件加速或 WebGL 不可用时能理解失败原因。
- 移动与镜头：W/A/S/D、拖动、滚轮正常；失去窗口焦点后不会持续移动。
- 尺度切换：按钮与 1—4 一致；快速切换不会卡在遮罩；各层位置在会话内保留。
- 同行：靠近提示正确；E 邀请、跟随与数量正确；最多 12 株；离开草层再返回不丢失。
- 对白：接近指定实体出现文字和来源说明；有冷却，不连续刷屏。草层的蚂蚁、瓢虫、蜗牛、蛛网与起点附近的大露珠也会回应。
- 草的感受：按 F 出现跟随自己的气泡；靠近未同行的草，它先说一句自己的感受；同行者偶尔开口；气泡不与对白面板同时出现，移出视野时隐藏。
- 天气与感知：约 4 分钟一轮（晴、云影、起风、小雨、雨后）；右侧感知面板的数值随之变化，天气切换时自己会说一句；下雨时天色变灰、有雨丝，雨后湿土变深、蚯蚓出现、露光更亮，高度缓慢增加。
- 草层分布：走到可行走范围的不同方向，花丛、露珠、土块与昆虫应随处可见，远处不应有明显的成片突然出现；三棵巨树位于边缘之外，接近时它们会说话。
- 人层与魂穿衔接（PR #9）：换人物后移动，R 成为树或岩石，确认人物面板、观察提示、能力遮罩和第一人称手部隐藏；环绕找到原身体再按 R，所选人物和离开的位置应保留。人物选择面板打开时，W/A/S/D、1—4 与 R 均不能改变当前身体或场景。自动回归见 `tests/e2e/human-embodiment.spec.js`：用真实输入和动画帧验证身体归属，CSS 视口不变，像素比降为 0.25 以减少软件 WebGL 栅格开销；不用于画质或性能验收，外观仍需人工复核。
- 人层草地：按 2 进入，脚边应有成片的密草，并能看到草穗与白色小花；W/A/S/D 走出一段距离，草毯始终铺在脚下，边缘不出现跳变或成圈的空地。拉远镜头并向下观察无遮挡的草坡，地面不应出现每隔约 11 米重复的深色斑块或方格接缝。检查水塘、屋舍和岩丘上没有长出草穗与小花，沿坡走动时草根贴地、不悬空。R 成为树或岩石后草毯跟着新的身体。系统开启减弱动态效果时，草叶、草穗和小花不再摆动。自动回归见 `tests/e2e/human-ground.spec.js`：对实际地面颜色贴图做分区亮度采样，限制会被重复放大的大块色差；它不替代场景光照与观感的人工判断。

2026-10-17 本地验证环境：macOS arm64、Node.js 22.23.3、Chrome 155.0.8059.80。feat-island 已同步 main 的 8fcdf0c，保留新版草层的感受、生长和天气；统一每帧 update(dt, time, reduced) 调用，草的生长只作用于原草身体，未配置魂穿参数的环境对白实体不参与 R 候选。`npm run check` 通过，包含格式、lint、13 项单元/仓库/服务器检查与静态构建。`PLAYWRIGHT_CHANNEL=chrome npm run test:e2e` 全部 4 项通过，约 5.2 分钟，使用真实 Chrome 与 SwiftShader 软件 WebGL，未替换渲染器或设置玩家位置。默认仍使用 Playwright Chromium；Chrome 是本机已有浏览器的可选通道，不降低断言。
