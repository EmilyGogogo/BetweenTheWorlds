# 验证与试玩

## 本轮 Earth V1 的执行分工

按用户最新要求，Codex 只运行不需要浏览器的代码逻辑、模块/API、Node 单元/集成、服务脚本、格式/lint/链接与构建检查，默认执行 `npm run check`。键鼠控制、画面、声音与实际流畅度由用户按 [Earth 手动检查单](earth-v1-manual-qa.md) 操作。

本轮 Codex 不启动/控制浏览器、不运行 `npm run test:e2e`、不下载浏览器，也不新增浏览器自动化用例。现有 E2E 文件、有效断言和 CI 保留；下方浏览器命令与覆盖说明保留作仓库参考，不是本轮每次本地修改的要求。用户这项明确调整优先于仓库默认 E2E 执行规则；交付标记“E2E 按用户要求未运行”，用户结果标“待用户检查”，均不写成通过。

精确逻辑由 Codex 测试，实际 DOM 事件接线、焦点、渲染与听感依赖用户检查。量化帧率与 heap 分析为条件性专项，不是日常眼检门槛。

## 自动检查

使用 Node.js 22.13 或更高的 22.x 版本。旧版本需要先升级；`.nvmrc` 指向 22.x，CI 使用该系列的最新版本。

```sh
npm ci
npm run check
npx playwright install chromium
npm run test:e2e
```

Linux 首次安装浏览器可使用 `npx playwright install --with-deps chromium` 补齐系统依赖。`npm run check` 依次检查格式、ESLint、单元与仓库完整性，再生成 `dist/`。浏览器测试直接使用这个发布目录，运行前需要已执行 `npm run build`。

单元与仓库检查覆盖原始附件/第三方文件哈希、文档本地链接、静态服务的资源类型及目录访问边界。浏览器冒烟在 Chromium 中创建真实 WebGL 场景，覆盖进入、移动、同行、对白显示、四层切换、帮助、声音开关、会话状态保留与刷新重置，并阻止外部资源请求。

冒烟测试在页面加载前暂停 Playwright 时钟，按 50 毫秒一帧推进真实游戏逻辑，对应游戏每帧允许的最大时间步长。移动距离与对白冷却按游戏时间验证，避免软件 WebGL 的低帧率导致实际等待超时；切换期间输入被锁定，直接推进两段淡入淡出定时器并渲染场景。测试不会替换渲染器、设置玩家位置或伪造对白。失败日志包含位置、当前尺度、对白和焦点状态，便于排查 CI 环境差异。

本轮移动回归还通过实际按键与位置诊断验证每游戏秒位移：草 `1.65`、人 `7`、岛 `15`、Earth `38`；Earth 使用对角线输入检查归一化，并检查松键停止及半径 `200` 的边界。位置诊断每 30 帧采样，测试在读取前推进空闲帧以刷新诊断，不通过直接写入玩家位置伪造结果。

当前自动化不代表所有边界已覆盖：12 株上限、对白的完整冷却时序、镜头拖动/缩放仍需人工验证。浏览器测试使用软件 WebGL，界面视口为 960 × 640 CSS 像素，像素比为 0.5，以减少 CI 的栅格计算量；它不是画质、真实声卡或性能验收，不进行截图比对。未安装 Chromium 时应明确记录未执行，不能当作通过。

本轮新增 Node 用例覆盖 Earth 邀请距离/资格/幂等、初始方向、长时间轨道、最新中心、暂停/减弱动态、实际工厂对象与资源身份、新会话重置，以及共享路由/提示 DOM 适配；纹理绘制使用 Node stub，不启动 WebGL，不代表画质或实际事件接线通过。具体结果见 [V1 QA 记录](earth-v1-qa-results.md)。

## 人工回归清单

记录提交版本、设备、浏览器、窗口大小、系统减弱动态效果设置及执行结果。

- 进入与错误反馈：正常加载可进入；禁用硬件加速或 WebGL 不可用时能理解失败原因。
- 移动与镜头：W/A/S/D、拖动、滚轮正常；失去窗口焦点后不会持续移动。
- 尺度切换：按钮与 1—4 一致；快速切换不会卡在遮罩；各层位置在会话内保留。
- 同行：靠近提示正确；E 邀请、跟随与数量正确；最多 12 株；离开草层再返回不丢失。
- 对白：接近指定实体出现文字和来源说明；有冷却，不连续刷屏。
- 声音：用户操作后开启；关闭确实静音；切换尺度音景合理；没有音频支持时仍可探索。
- 帮助与键盘：打开/关闭/Escape 正常，文字可读，主要按钮有焦点标识；弹窗完整焦点管理仍是待办。
- 画面与性能：四层无明显渲染错误；不同尺寸下操作入口可见；记录测量数据和卡顿路径。
- 减弱动态效果：检查摆动、旋转与切换，记录当前未遵循偏好的具体行为，不提前声称完全支持。
- 刷新：回到欢迎与初始状态；开发版与离线原始 Demo 的基线行为可对照。

## 如何报告结果

提交命令和输出摘要，或实际设备上的操作路径与观察。CI 的 Linux/Windows 检查和浏览器检查在 GitHub 运行后才算远端验证；本地 Windows 通过不能写成已验证 Linux、Safari 或移动端。

## V2 的非浏览器回归与用户检查

延续用户指定分工，不运行/新增浏览器自动化、不下载浏览器；保留已有 E2E/CI。新增 earth-sun/earth-actions 的 Node 测试覆盖实际场景矩阵、距离强度、响应/冷却边界与余dt、暂停、组合优先级、启停恢复和重复资源引用；原 Moon测试保留，talkers库存明确更新为三条。结果见 [V2 QA记录](earth-v2-qa-results.md)，用户执行 [S1–S7](earth-v2-manual-qa.md)。

可选性能与heap分析分开运行：普通演示配置采帧时间，诊断会话才尝试DevTools Collect garbage。普通页面没有window.gc或不支持可靠GC/heap是预期情况，记未验证，不配置自动化来强行完成；不以诊断会话的帧率作为正常性能基线。

## V3 的非浏览器回归与用户检查

按相同分工执行`npm run check`，不运行/新增浏览器自动化、不下载浏览器，保留已有E2E/CI。新增world-movement与earth-ringed-planet测试：真实生产正常位移、四层速度/边界、输入锁存、非法请求、实际反馈与预算、真实工厂组合、2秒/12单位/6秒边界、暂停/取消、启停、减弱动态与资源引用稳定。全部原38项有效测试不删不放宽。主循环事件与镜头顺序另作源码审查，真实事件接线和显示依赖用户[T1–T7](earth-v3-manual-qa.md)，记录见[V3 QA](earth-v3-qa-results.md)。

可选heap/GC诊断使用单独的诊断会话，可能需要启动标志、CDP或DevTools；普通页面不能可靠强制GC是预期情况，记未验证，Node引用稳定不能证明无泄漏。正式性能使用与基线一致的普通无特殊标志配置，避免诊断/DevTools开销，不混用两个会话的帧时间。两项均不是日常手验前置。
