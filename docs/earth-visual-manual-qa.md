# Earth视觉：你的浏览器检查单

代码与非浏览器QA就绪；以下未运行。Codex不控制浏览器、不运行E2E。按[V3检查单](earth-v3-manual-qa.md)的原语义测试互动，不把本次美术变化当新玩法。

## 先做日常眼检（V1–V7）

项目目录执行`npm run dev`，打开终端地址，刷新进入并按4。下面每项反馈“通过/失败+现象”即可。

| 编号        | 你做什么                                                                 | 通过标准                                                                                                                        |
| ----------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| V1 星空     | 默认观察；拖动环绕360°；滚轮最近/最远                                    | 深蓝暗区、银河/暗尘及细小圆星有层次；背向仍有星；没有明显接缝/方片、星穿过天体或随移动近距离漂移                                |
| V2 Earth    | 观察海陆、拉近看云；帮助停留5秒再关；开系统Reduce Motion并刷新重复       | 海陆与薄云分开，云不穿壳，薄蓝边/暗面可辨；帮助冻结地表/云，关闭后无时间追赶；减弱动态冻结地表/云漂移                           |
| V3 Moon     | 靠近月亮正常距离和近看，再按E邀请；移动/切层再回                         | 是灰色坑纹岩体，受光有层次；只有一颗Moon，轨道/随行继续，表面不金属/塑料发亮                                                    |

每组保存默认全景、Earth近景、Moon、Sun、有环星球、背向星空六张截图。旧版命令见下节，同样位置/镜头/窗口对照。请另一位试玩者先看10秒，说他最先注意到的主体和最想靠近的对象（无需评价术语）。

**出现黑屏/天体消失/Console Shader编译错误请先反馈原文。** Node不能验证实际GPU编译，不能把非浏览器通过当作这一项已过。

## V0 / V8：旧版基线与新版三轮真实帧采样

这是完整S0与量化性能验收所需，和日常眼检分开记录。当前没有任何真实样本，不声称相对增幅达标。

旧版worktree本机已准备。新克隆没有该目录时，先运行`git worktree add --detach .local/earth-visual-baseline c97b8bb`。分别在两个终端启动（Node22，端口占用可改；保持两版窗口条件相同）：

```sh
node scripts/earth-visual-qa.mjs --baseline --port=5174
node scripts/earth-visual-qa.mjs --port=5173
```

- 旧版：`http://127.0.0.1:5174`，冻结在c97b8bb升级前代码。
- 新版：`http://127.0.0.1:5173`，当前视觉；两版使用同一手动采样工具。此工具只存在于开发QA服务，不进入生产页面。
- 不用软件WebGL、模拟时钟、强制GC或开着DevTools性能录制的诊断会话。使用普通硬件加速浏览器；写明浏览器完整版本/渲染后端、设备/CPU/GPU/内存、刷新率、窗口尺寸、DPR、Reduce Motion、音频、电源状态。未知项写未知，完整验收前补齐。面板环境JSON填实际device、cpu、gpu、memoryGiB（数字）、os、browserVersion、refreshHz（数字）、power、hardwareAcceleration（核实后true）；unknown可保存原始记录，但统计工具会拒绝把缺环境证据的样本判Pass。JSON自动包含视口/DPR等可读字段和实际renderer计数。

每一轮都刷新，从新会话开始：

1. 点击进入；依次按1、2、3、4，每层实际显示后停留至少3秒、让资源计数稳定。不要先邀请Moon或按任何E，不拖镜头/缩放。
2. 回到初始Earth，在面板填写相同环境JSON，点击“开始60秒实帧采样”。
3. 前20秒松键；按面板提示做5轮W 2秒/S 2秒；后20秒松键。提示切换前后350ms为两版一致的人类反应窗口，实际按键全部保留。不要切窗口、帮助、拖镜头或改尺寸/DPR/音频。
4. 满60秒自动下载JSON。若显示无效，保存该次原因，刷新重做；不要删慢帧、只挑最好一轮，或把未知环境当已确认。
5. 旧版重复三轮B1–B3，新版重复三轮A1–A3。每轮都刷新重新预热；JSON带版本、源码指纹、每帧时间戳与实际资源计数。将全部有效/无效记录保存到`docs/evidence/earth-visual-performance/`，告诉Codex文件名即可。

Codex会复算中位帧时间、nearest-rank P95、draw calls中位/峰值、geometry/texture起始/峰值/结束，核对所有样本环境/路线。三轮统计取中位数，再比较前后中位帧时间和P95增幅是否都<=10%。缺数或条件不同则未量化，不使用主观“流畅”替代。

可选GC/heap诊断另开会话，非本次日常手验前提。
