## 1. 三个版本的体验差异

| 版本         | 体验                       | 结果                                         |
| ------------ | -------------------------- | -------------------------------------------- |
| V1：月亮     | 邀请一个独立天体同行       | 原月亮围绕 Earth 公转，关系在本页保留        |
| V2：太阳     | 接近受光并主动回应         | 有界的光照和一次短暂外观变化                 |
| V3：有环星球 | 自愿短暂感受另一天体的影响 | Earth 实际位置发生少量、受边界限制的牵引位移 |

V3 不要求玩家已有月亮，也不要求成功回应过太阳。普通 Moon 跟随最新 Earth 位置、Sun 随距离更新光照属于原规则继续运行，不是基于关系解锁的组合事件。Moon–Sun–行星的特殊联动留到 V4。

## 2. 玩家体验

```text
发现已有有环星球 → 靠近并松开移动键
    → 看见“E 感受引力 · 移动即可中止”
    → 按 E → Earth 向它缓慢漂移，星环给出一次局部响应
    → 约 2 游戏秒后结束，或按任意移动方向立即结束
    → 继续正常移动，短冷却后可再次体验
```

默认没有被动引力：仅仅靠近不会自动拖走玩家。此次重点是可感知且可信的有限运动变化，不是建立持续受力、惯性或多体系统。

牵引时共享跟随镜头继续观察 Earth，不抢镜头角度、不锁键、不强迫镜头绕行。玩家按 WASD/方向键即可取消，随后按原规则移动。没有伤害、失败、资源消耗、分数或轨道捕获。

## 4. 本次范围

### 包含

- 对原有环星球增加主动作资格与一份局部状态。
- 一次最多约 2 秒、总额外位移有上限的水平牵引。
- 玩家移动即时取消，边界/对象失效时安全停止，结束后有短冷却。
- 星环的一次轻微视觉反馈和既有 toast 成功反馈。
- 一个受控的共享运动接入点，确保运动、Moon、Sun、相遇和镜头使用同一最终位置。
- Moon/Sun/有环星球的动作选择、状态共存、非浏览器验证及用户操作验收。

### 排除

新增行星、真实质量/万有引力常数、加速度/惯性系统、N 体模拟、重力弹弓、玩家绕行星公转、碰撞、运动升降、扩展移动边界、自动跟踪镜头、伙伴条件事件、太阳联动、音效系统、存档、相遇概率配置和通用物理框架。

如果产品方更希望“土星共舞”或“木星弹弓”，应另改机制和验收，不在实现本方案时顺手添加。

## 5. 资格、参数与可达性

### 5.1 主动资格

同时满足以下条件才显示并允许动作：

1. Earth 活动、游戏已开始、帮助关闭、未转场，`context.canInteract=true`。
2. 原有环星球仍存在于当前 scene，且没有被外部配置禁用。
3. 局部状态是 `ready`，Earth 与行星中心的三维距离在动作范围内。
4. 玩家当前没有按移动键；需要读取实时输入，不能仅信赖上一帧的 `w.moving`。
5. 水平方向有效，并且牵引方向在共享圆盘边界内仍有实际位移空间。

查询无副作用；按 E 时重新检查。不等待随机对白，不从旧提示缓存授权，不用扩大 `talkers.range` 代替资格。

### 5.2 建议初值

| 参数             | 初值 / 约束                                                                |
| ---------------- | -------------------------------------------------------------------------- |
| 行星位置         | 先保留 `(-150,40,-230)`                                                    |
| 主动范围         | 中心三维距离 `<=130`                                                       |
| 牵引失效外范围   | `160`，与主动范围分开，避免边界附近频繁切换                                |
| 额外牵引速度     | `6` 场景单位/游戏秒                                                        |
| 最长主动时间     | `2` 游戏秒                                                                 |
| 最大额外路程预算 | `12` 场景单位；按实际应用的牵引路程控制，不含玩家正常位移                  |
| 冷却             | 停止或取消后 `6` 游戏秒                                                    |
| 边界资格探测     | 沿牵引方向试算 `1` 单位，无需夹取且有效位移大于 `0.05`；待调初值           |
| 星环视觉反馈     | 在原材质/变换上做一次轻微变化，原透明度 `0.8`，建议不超过 `0.95`；结束恢复 |

这些不是已验证的手感、视效或性能结果。基础移动速度仍为 `38`；牵引期间默认不叠加玩家输入，任何方向输入都会先取消牵引，然后正常移动。

当前行星水平距原点约 `274.5906`，中心在玩家圆盘外。玩家在半径 `200` 边界上朝向它时，最近三维距离约为 `84.6`，所以主动范围 `130` 可达；不能要求玩家抵达行星中心。

启动探测不能依赖夹取产生的侧向滑移：沿方向试算1单位应仍在圆盘内，且有效位移>0.05。活动牵引若首次发生夹取，仅计该帧实际位移后停止并冷却，不继续沿边滑行。边界上的正向牵引可能被夹取为零，此时不显示一个实际无法执行的动作。应在更靠内的位置可启动；接近边界后停止。若实际构图或与 Sun 提示重叠导致难发现，先记录可达路径，再协调调范围或布局，不默认扩大共享边界。

## 6. 运动行为与中止规则

牵引方向取“行星中心减 Earth 最新位置”的 X/Z 分量并归一化，Y 不改变。以统一 dt 计算本帧位移，最后一帧截断到剩余时长和剩余路程预算；不使用帧数或真实墙钟计时。

牵引向量只是额外位移请求。Earth 局部模块不能直接写 `avatar.position`，也不能在最终边界夹取后偷偷改变 `w.position`。实际应用与最终夹取由共享移动阶段完成。

| 事件                           | 行为                                                       |
| ------------------------------ | ---------------------------------------------------------- |
| 有效 E                         | 进入 `pulling`，一次反馈，例如“引力，轻轻改变了你的方向。” |
| 按任意 WASD/方向键             | 本帧先取消牵引，不再施加其位移；玩家输入正常生效，进入冷却 |
| 没有移动输入                   | 最多持续 2 游戏秒，并受 12 单位额外路程预算限制            |
| 方向退化、行星失效、离开外范围 | 停止牵引并进入冷却，不生成替代对象                         |
| 到达无法继续牵引的边界         | 停止，不持续向边界推、不越界、不抖动；已有反馈不循环刷屏   |
| 帮助/欢迎/转场或非活动         | 牵引/冷却计时冻结，无额外位移；对象失效清理例外，不扣冷却  |
| 返回 Earth                     | 从保留状态继续，先重查当前资格和方向；不补算离开期间的位移 |
| 刷新                           | 重置为 ready，不影响原世界初始对象规则                     |
| 连按/长按 E                    | 不叠加速度、不重开计时、不跳过冷却、不执行另一个世界的动作 |

建议状态存为 `w.earthState.ringedPlanet`：`ready → pulling → cooldown → ready`。保留既有 moon 和 sun 子状态，不重新赋值整个容器。

冷却在活动且允许模拟时推进，无需留在附近。非法、零或负 dt 不推进状态或施加位移。暂停与中止必须区分：帮助是冻结，移动键是结束本次体验并进入冷却。

## 7. 必须先对接的共享运动入口

### 7.1 当前接口缺口

V2的 `main.js` 先在有输入时更新 `w.position` 和夹取边界，再调用 `w.update(context)`。若在普通 update 中直接牵引，会发生：

- 无输入时绕过现有夹取，Earth 可能超出半径 200。
- Moon 或 Sun 更新早于牵引，跟随/光照使用旧中心。
- 其他代码与轨道各自改位置，难以验证位移预算和中止顺序。

因此V3通过可测试的共享运动辅助接入，而非在普通update中直接改位置。授权与调用方见 [ADR 0004](decisions/0004-earth-ringed-movement.md)。

### 7.2 已落地的最小契约

```text
读取实时玩家输入、刷新 context
    → 应用原有玩家移动并保留原夹取（取得玩家移动结果基点）
    → 查询活动世界的可选运动影响
    → 校验/应用该位移请求
    → 无论玩家是否有输入，都夹取最终位置
    → 行星消费实际结果/中止状态，然后Moon、Sun各更新一次
    → 镜头、提示与共享相遇检测
    → render
```

本计划建议 `world.getMovementInfluence(context, out)`：仅向调用方提供的复用输出缓冲写入 `{x,y:0,z,duration}`，返回该缓冲或null，不推进业务状态/计时、创建资源、改位置或写DOM。共享阶段唯一应用一次，随后用带stepId的结果反馈；该API已在本轮代码中落地。具体契约和逐步QA见实施分步。

现有 `refreshActionContext()` 在提示与E执行时默认dt=0，因此资格/启动不得要求正dt；只有运动查询和逐帧计时要求合法正dt。这样不需改现有主动作语义。

context 需沿用统一 dt、canSimulate/reducedMotion，并按职责补充：

- 实时 `hasMovementInput`：任一WASD/方向键按住即为true（即使W+S相互抵消）；E执行时与运动查询时都读取当前键集合。另用 `movementInterrupted` 锁存方向keydown或blur直到运动阶段处理，避免RAF前松键漏掉中止。
- 当前层的 `movementLimit`：来自已有参数表，不在 Earth 模块再硬编码另一份 200。
- 本帧 `movementResult`：stepId、是否接受、实际x/z/长度、请求duration、是否夹取/完全阻挡及拒绝原因。只从正常输入夹取后的基点计影响；行星对同step结果只消费一次，无匹配结果不自行猜位移/预算。共享上限从Earth提供且被实际消费的冻结limits读取（6单位/秒、单次最多12），不得散落硬编码。

共享层对请求校验有限数值、Y 为零与已约定的速度/路程上限。边界夹取必须作用于最终位置，包括无玩家输入的纯牵引帧；没有提供入口的其他世界继续原移动行为。

如果首次发生夹取或完全阻挡，局部状态消耗本帧真实路程后立即结束并开始完整6秒冷却；取消帧不扣冷却，不无限重试或沿边滑行。正常时长/预算完成则消费该帧合法剩余dt，1e-9秒容差处理浮点边界。帧末以同一个最终 `w.position` 更新月亮、太阳与镜头，Earth 原自转仍保持一处。

这是一次需要共享协调的小型移动接入，不是新增物理引擎。按 [决策模板](decisions/template.md) 补充实际契约、输入阻挡、结果反馈、全部调用方和回归证据。本轮main仅接线，正常运动计算与影响校验在world-movement.js；调用方和证据见ADR。

## 8. Moon、Sun 与行星的组合

### 主动作选择

建议延续 V2 顺序：**可邀请 Moon → 可响应 Sun → 可体验有环星球 → 无动作**。每个候选只在自身资格满足时参与，提示和执行使用同一无副作用选择函数。

范围重叠时保持固定优先级，不随机选动作或在两条提示间闪烁。需要验证实际布局存在可直接使用行星动作的区域，不能强迫玩家先招募 Moon 或回应 Sun 才能看到它。如果没有独立可达区域，调整局部范围/布局方案后再实施，而不是偷偷改变优先规则。

Sun 与组合器已经实现；V3直接扩展真实的 earth-actions 调度，保留现有38项非浏览器检查及用户确认的V1/V2结果，不增加占位分支。

### 局部更新与视觉归属

- Earth 层只安装一套组合回调，Moon、Sun、行星各更新一次，不能由新 helper 覆盖旧函数。
- 牵引实际位移先完成，Moon 再按新中心跟随，Sun 再计算距离与受光。
- 行星视觉反馈只修改原 `gas/ring` 的局部属性，保存一次基线并在结束/取消后恢复，不覆盖 Sun 灯光或 Earth 大气颜色。
- Sun 响应可以按其原规则自然持续，Moon 正常随行；不增加“有月亮时引力更强”等关系条件。
- 除既有场景缓存，不增加全局注册表、物理管理器、伙伴复制体、RAF、定时器或监听。

## 9. 减弱动态与玩家控制

建议保留由玩家按 E 明确请求的短暂低速位移，并在提示中说明“移动即可中止”。减弱动态模式不增加星环旋转/脉冲、镜头摇晃或视野缩放，使用稳定轻微的局部反馈；Moon/Sun 沿用各自的减弱动态策略。

这不是被动持续运动。若用户眼检表明该模式仍不舒适，改为无自动位移的替代回应需要在实施前明确验收差异，不能测试中悄悄禁用核心机制再声称所有模式都具有牵引玩法。

不要求新增取消快捷键；任意原有移动方向立即接管。停止、边界反向移动、失焦后无按键残留等共享规则应保留。blur会锁存中止：下次运动阶段不再牵引，进入完整6秒冷却，回来不自动恢复旧牵引；不改变Moon/Sun原有失焦行为。

## 10. 相遇与内容边界

沿用已有有环星球的 talker 和内容来源。主动成功反馈通过已有 toast 返回，不调用共享 `say()`、不改 `lastTalk`、不触发强制开场对白。

主动动作的 6 秒冷却仅防止反复施加运动影响，不是相遇频率参数。外部相遇概率、生成策略、共享 19 秒对白冷却仍由原负责人控制；对象被禁用时尊重其结果，不补造一颗“必遇土星”。

对象管理采用内部显式启停，与Sun一致：禁用隐藏原对象、移除准确的原行星talker、停止影响并恢复星环；pulling进入完整6秒冷却，原cooldown保留，ready仍ready，禁用期间冻结。重新启用复用同一Group/材质/记录并保留剩余冷却，不重建、不重复push、不靠启停绕过冷却。意外移出scene/隐藏/引用失配时查询与执行无副作用地拒绝，下次活动update即使暂停也清理；不得擅自重新挂回被移走对象。其他对象/对白不变。

若要扩充短句，保持原创/改写来源说明；不因为“引力”机制加入未经核实的天文结论或哲学家原话。
