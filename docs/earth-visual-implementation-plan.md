## 2. 锁定的画面目标

采用提案已选定的 cinematic natural space。概念图作为颜色、材质和空间层次参考，不承诺复制其真实地理、夜景、太阳射线或密集碎石。

视觉顺序为 **Earth → 可接近的天体 → 银河与星场**。Sun 允许是最亮点，Earth 依靠面积、轮廓和材料层次成为视觉中心。银河的亮结点避开默认左侧文案，背景方向固定在世界坐标；玩家转动镜头时，用 UI 局部底色继续保障文字可读。

| 元素     | 起始美术设定                                              | 应能观察到的结果                           |
| -------- | --------------------------------------------------------- | ------------------------------------------ |
| 太空底色 | 近黑蓝 `#050914`，保留大片暗区                            | 有深度，不像亮蓝色摄影棚                   |
| 星点     | 约 85% 微弱、14% 中等、1% 亮星；中性白为主，少量暖白/冷白 | 有大小和亮度层次，能看出圆核，不像统一噪点 |
| 银河     | 一道宽而低对比的倾斜带，亮度密度与暗尘同时存在            | 默认镜头可辨认，转身有连续而更稀疏的延伸   |
| Earth    | 深蓝海洋、低饱和绿褐陆地、薄白云、克制蓝边                | 正常距离就能区分云、海、陆，夜侧仍有轮廓   |
| Moon     | 冷灰尘土、大小不同的坑与暗区                              | 坑缘随 Sun 方向受光，避免塑料反光          |
| Sun      | 暖白主体、金色颗粒与柔和短晕                              | 球面有细节，不用巨幅光芒抢走整个画面       |
| 有环星球 | 米褐气体带、细密薄环与少量间隙                            | 与 Earth/Moon 材料明显不同，前后遮挡可信   |

星点比例和色值是试做起点；最终以正常缩放和实际演示屏幕判断。亮度不能只在极近镜头或高亮截图里成立。

默认构图沿用现有对象位置与镜头：

```text
┌──────────────────────────────────────────────────┐
│ 现有品牌/帮助                暗星场与银河延伸     │
│                                                  │
│ 左侧章节文案    可接近天体       Earth 视觉主体    │
│ 低对比背景      位置沿用现状     云/海陆/薄蓝边    │
│                                                  │
│       现有对白与 E 提示：背景上也必须可读          │
│              底部现有四层导航                    │
└──────────────────────────────────────────────────┘
```

这是层级示意，不是重新摆放 Sun、Moon 或有环星球的屏幕坐标指令。天体不必同时完整入镜；拖动和移动仍由玩家掌握。

## 4. 背景的具体实现

新增 `src/worlds/earth-background.js`，只负责 Earth 的天空对象与一次性生成资源；返回一个 sky Group，交给 `space.js` 挂到 scene 并保存为 `w.sky`。

- 天空底层是一张可环绕的程序密度图，包含星际底色、银河密度、暗尘；贴在从内部可见的球面。首选球半径约 2,000，独立星点约 1,600，均在有效 far=3500 内。
- 保留 4,200 个星点与单个 Points 合批，增加每点大小/亮度属性；局部 Shader 用 `gl_PointCoord` 形成软圆核，不需要外部星点图片。优先采用屏幕大小受控的点，检查不同窗口/DPR 的可见性，避免直接沿用远距离衰减后仍全部太小。DPR 可由对象的 `onBeforeRender` 获取 renderer 的实际像素比，不为此扩大共享 tools 或镜头接口。
- 全向贴图按球面方向采样低频噪声，叠加窄宽不同的银河密度与暗带；经线周期连续，极点不堆亮斑。新增星点分布也沿银河略增密，不能只在模糊底图上画一道亮线。
- 背景不写深度；星点保留对主体的深度测试，不能穿过 Earth 或 Moon。明确背景绘制顺序，球内表面可见，不能靠关闭所有 depthTest 让星空浮到主体前面。
- sky 只跟随相机平移，不复制相机旋转；移除原 scene 上独立的星点/尘埃对象，防止双背景和不同漂移。
- 不为新背景注册 talker、动作候选或移动影响。第一轮不闪烁、不旋转整片银河。

新增生成器使用 Earth 局部固定种子。旧背景使用共享 `rand`，替换其生成逻辑会改变后续共享随机流的消费位置，可能改变其他层首次生成的随机细节或对白抽样序列；要在差异说明中披露，不能声称随机序列完全不变。现有相遇算法、概率规则与冷却保持原样，不借机重构全项目随机系统。

P1 岩体先放在水平半径约 320–650 的候选区域，留在玩家半径 200 的移动圆盘之外；按实际岩体尺寸留足 Earth 与已邀 Moon 的包络余量，同时避开 Sun、原有环星球与主要观察路线。几何实例共享资源，不设碰撞、招募、对白或发光提示；默认镜头与移动到边界后都要检查遮挡，不能只证明中心点在圆盘外。

## 5. 四个天体的材质方案

新增 `src/worlds/earth-materials.js`，集中实现本次实际使用的贴图生成；颜色图使用 sRGB，roughness/bump 等数据图使用 NoColorSpace。所有输出在建世界时生成一次；不在每帧、E 互动或切回 Earth 时重画。

### Earth 与云

1. 由同一套可无缝球面采样生成大陆遮罩：大轮廓、多尺度海岸和低幅度地表变化。海洋深浅与陆地绿褐过渡分开，移除原色图中的云斑。
2. 地表继续使用 MeshStandardMaterial。一个数据图的 R 存高度、G 存粗糙度，分别供 bumpMap 与 roughnessMap 复用；海洋较光滑、陆地较粗糙，金属度保持 0。首轮不做几何位移。
3. 独立云壳半径起点 23.35，位于地表 23 与大气 24.1 之间；挂在 `w.avatar`，复制地表轴倾角并保存初始自转关系。用一张带 alpha 的云图和透明、受光材质，降低云覆盖率，确保海陆仍能读出。
4. 地表保持原自转速度 0.018rad/游戏秒；云使用独立的略有差别的速度，例如 0.020。两者均在唯一 visual update 内推进，不能重复继承/叠加完整自转。减弱动态时冻结自转与云漂移。
5. 保留原 `w.atmosphere`、color uniform 对象及基础 opacity=0.65 的兼容性；先通过边缘衰减曲线调薄，不添加第二个大气光圈。V2 继续独占其响应变色。
6. 先沿用 Sun 主光基线 3.8 与现有接近增强。若环境光 1.1 冲淡日夜层次，只调 Earth scene 的 AmbientLight；可从 0.35–0.6 试起，直到暗面可读。数值是调参候选，需要实机确认，不修改全局 exposure 或其他世界光照。

云不投影、不生成城市灯光；此处“受光”指云材质响应现有 Sun，不表示已经实现云层对地表的阴影。

### Moon

- 建立时将原 Moon 的几何设为半径 9、约 64×40 分段的 SphereGeometry；材质继续为粗糙、非金属的 MeshStandardMaterial。
- 固定种子生成稀疏大暗区、不同半径陨石坑及较细小坑；颜色与高度来自同一结构，坑缘、坑底不能各自随机脱节。
- 高度图只控制微小凹凸，不改变包络与邀请距离。保留可被后续 V4 使用的 color/emissive，基础 emissive 不做常亮补光。
- 原 Moon Mesh、scene 父关系、talker 引用、半径 48/高度 5 的轨道继续使用，不额外复制装饰月亮。

### Sun

- 保留原 Sun Group 的两个子对象、原 MeshBasicMaterial 类型和 halo；在球体材料上挂暖白/金色颗粒图，先以静态表面完成验收。
- halo 优先调整现有 Shader 的柔和衰减，保持 uniform/scale 接口；不扩大基础几何，不用整屏 bloom 或 lens flare。
- 若静态效果不足，再由同一 visual update 加非常缓慢的表面旋转；不增加第二套时间源或改 V2 3秒/5秒状态机。
- 自定义背景/halo Shader 的颜色输出需与当前 r170 渲染管线核对，避免重复转换颜色或遗漏转换。Sun 的 `toneMapped:false` 与其他材质的 ACES 输出要在同一画面校准。

### 有环星球

- 给原 gas 球体生成低饱和条纹，加入少量纬向扰动；保持原球半径、Group 倾角、位置及两个子对象结构。
- 为原 RingGeometry 重新计算径向 UV；用颜色+alpha 图表达细环/间隙，替代原粗粒度正弦顶点色表现，避免两套条纹相乘变黑。
- 保留 DoubleSide、depthTest，优先使用 `depthWrite:false`，使不透明球体自然挡住后方环；实机检查斜视、背视与透明云层交叠。不把这项描述为真实投射环影。
- 原 ring 材质在动作处理器创建前设置完成；保留 opacity 基线 **0.8**、V3 普通峰值 **0.95**、减弱动态反馈 **0.88**。细分透明度放在贴图 alpha 中，视觉更新不写 material.opacity。

## 6. 更新接线与字段所有权

`space.js` 的初始化顺序必须为：创建对象 → 设置基础纹理/材质/halo → 创建 Moon/Sun/V3 动作处理器捕获基线 → 创建 visual update → 一次调用 `installEarthActions`。

视觉批次已在签名尾部增加可选 options，容纳 visualUpdate；V4 在同一 options 中另加可选 relationship，旧的三参/四参调用继续有效。当前 `earth-actions.js` 仍是唯一 world.update 安装者：

```text
main：现有移动与 V3 影响/夹取
  → ringedPlanet.update(context) 一次
  → moon.update(context) 一次
  → sun.update(context) 一次
  → relationship.update(context, sunView) 一次（V4）
  → visualUpdate(context) 一次
  → 原镜头/提示/相遇/渲染
```

V4 的 Sun 动作成功后，还在该动作调用内同步一次 dt=0 关系视图，不重跑 Sun.update 或消费时钟；这不增加第二个模拟循环。

视觉批次已从 `main.js` 移除对应的无条件 Earth 自转那一行，将其迁到 visual update；这是本轮对共享控制器的必要小改。新更新只使用合法正 dt、上限 0.05，要求 `canSimulate`；减弱动态冻结非必要循环。帮助、转场、非活动世界不推进新动画，原动作失效维护仍由各处理器执行。

| 字段或资源                         | 基础视觉负责                     | 动作模块继续负责                       |
| ---------------------------------- | -------------------------------- | -------------------------------------- |
| Earth 地表/云、Moon 坑纹、gas 条纹 | 初始化及自有旋转                 | 不改互动状态                           |
| 大气材质与 color uniform           | 初始化完成后保留引用             | V2 的变色、结束/禁用恢复               |
| Sun halo 基础材质与 scale          | 初始化完成后不逐帧改 scale       | V2 的一次缩放响应与恢复                |
| ring 材质与贴图 alpha              | 保留 material 身份与 opacity=0.8 | V3 的 opacity 包络和停止恢复           |
| Moon color/emissive                | 建世界时设基础值；保留 map/bump  | 已实现 V4 独占临时 emissive 贡献与恢复 |

视觉模块不写 world.position、运动请求、Moon 轨道、Sun 灯光计时或主动作优先级。V4 已通过实际 earth-relationships 接入，非空预留处理器；不反过来让基础视觉模块写关系状态。

## 9. 资源与性能预算

下表是完整 P0 的规划上限；颜色图与数据图分开列，避免把共享引用重复计费。按 RGBA8、完整 mip 粗估，不等同于实测 GPU 分配或 Canvas/CPU 峰值。

| ------------ | --------- | --------------------------------- | ----------: |
| 天空密度颜色 | 2048×1024 | 背景；P1 星云/小星系优先烘在同图  |       10.67 |
| Earth 颜色   | 2048×1024 | 海陆，不含云                      |       10.67 |
| Earth 数据   | 1024×512  | R高度/G粗糙度，两个材质槽复用     |        2.67 |
| 云 RGBA      | 1024×512  | 单层云颜色与透明度                |        2.67 |
| Moon 颜色    | 1024×512  | 坑纹与暗区                        |        2.67 |
| Moon 高度    | 512×256   | bump                              |        0.67 |
| Sun 颜色     | 1024×512  | 原 BasicMaterial 的 map           |        2.67 |
| gas 颜色     | 1024×512  | 大气带                            |        2.67 |
| ring RGBA    | 1024×64   | 径向颜色与 alpha                  |        0.33 |
| 合计         | —         | 原 Earth 贴图被替换，不再叠加保留 | **约 35.7** |

纹理总估算低于提案 48MiB 的新增预算，但必须加上几何、引擎实际格式与 CPU 生成峰值再评估。云层新增约一个 draw call，天空替换原两组 Points；P1 岩体用少量共享几何/材质的 InstancedMesh。全路线新增 draw calls 目标仍为约 12 以内，以实际统计为准，双面透明材质可能多次绘制。

资源随现有缓存世界存活到页面结束；不在每次互动/切换时 dispose。初始化若替换了已创建的旧纹理/几何，确认不共享后立即释放旧资源；优先直接创建最终资源，避免先造旧版再替换。资源收集应覆盖 map、bumpMap、roughnessMap、Shader uniforms，不能只检查 material.map。

记录第一次进入/再次返回、同设备同视口/DPR 的 draw calls、纹理库存与日常帧时间。`canvas.dataset.drawcalls` 已可提供活动场景绘制调用诊断。以稳定 30FPS 为演示目标，未测前不作保证；生成时间目标是尽量藏在现有转场内，超出时先降非关键纹理和噪声计算成本，不默认引入 Worker、自动画质或新依赖。

### 相对性能验收（对应审阅 8-D）

完成 0-C 后，S7 在每个实际交付阶段按同一协议采集 A1–A3，绑定该阶段版本与资源清单；不能只测后来的完整版本替代首批成本记录。基线 B1–B3 与后测 A1–A3 的设备、设置、四层预热及 R1 路线必须一致，记录采集开销；原始三轮均可查。条件改变则建立新基线，不混用不同机器/版本的旧数字。

预先固定汇总方法，避免挑选最好样本：`B_median` 是 B1–B3 各轮帧时间中位数的中位数，`B_P95` 是三轮 P95 的中位数；A 同理。分别计算 `(A_median/B_median-1)×100%` 和 `(A_P95/B_P95-1)×100%`，**两项增幅均不得超过 10%**；同时展示每轮原值、draw calls 与资源计数变化。稳定 30FPS 的目标需结合实测帧时间另行判定，不能仅因相对增幅合格就宣称达到 30FPS。

缺少任一有效样本、环境/路线不一致、基线为零或无法复算时，此项为 Blocked/未量化；超阈值为 Fail，优化后按同协议重新采齐三轮。数值型门槛未满足时不写性能通过；普通试玩的“感觉流畅”不能替代该门槛。
