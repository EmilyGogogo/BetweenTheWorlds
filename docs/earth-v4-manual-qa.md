状态：待用户。Codex 已执行的非浏览器结果见 [QA 记录](earth-v4-qa-results.md)。无需自动化浏览器、开发者控制台或内存工具。完成后回复通过编号或失败编号与现象即可。

## 准备与路径

项目目录执行 `npm run dev`，打开显示的地址，刷新进入游戏，按 **4**。每次对照测试先刷新、保持原 Earth 身体，不按 R；Sun 可被 R 接管移动，因此刷新可保证布局一致。

默认镜头下，Moon 在右前方，Sun 在左前方。W 向前、A 向左、D 向右；若转过镜头，按实际画面靠近，不把按键时长当坐标保证。

- solo：从起点向左前方 Sun 移动（W+A 约两秒后微调），直到出现“E 回应光芒”；途中不要邀请 Moon。
- duet：刷新，向右前方 Moon 靠近（W+D 短按约一秒后微调），出现“E 邀请月亮同行”后按 E；再带 Moon 向左前方 Sun 移动，直到出现“E 与月亮回应光芒”。松开方向键后观察最清楚。
- 普通响应约 3 游戏秒，随后冷却 5 游戏秒；卡顿会让游戏秒慢于真实秒，以提示重新出现为准。Sun 不会因 E 跟随 Earth，Moon 沿用原来的同行/轨道。

## 限制与结果

- 已有风险：R 接管 orbiting Moon 时，旧 Moon 跟随更新可能覆盖玩家位移。V4 不修改该旧行为。若遇到，单列反馈；不能把它写成已修复，也不能用这条备注掩盖任何新增合奏残留或新回归。
- 程序内部完成标记由 Node 测试验证，无需你在控制台检查。可辨认度、控制、实际 Shader/画面由你判定。
- V3 T1–T7、视觉 V0–V8 旧记录仍未收到通过确认，本表不自动关闭它们。
- 正式性能/heap 专项未执行；本轮无需采三轮帧率或强制 GC。若后续执行，普通性能与 flagged/CDP GC 诊断分会话，保存原始数据，不能混用基线。
