# Earth V1：用户浏览器检查单

QA 分工：Codex 执行代码逻辑、模块/API、Node 单元/集成、静态服务与构建检查；你负责浏览器里的键鼠、画面、声音和体验。Codex 本轮不控制浏览器、不运行 Playwright/E2E。关联 [实施计划](earth-v1-implementation-plan.md)。

**V1 手动浏览器检查已由用户明确确认通过。** 本表保留作操作参考；V2 修改后的组合回归见 [V2检查单](earth-v2-manual-qa.md)，不需重问V1验收。M9/M10量化专项未执行，不视为性能达标或无泄漏证明。

## 启动

在项目根目录 `BetweenTheWorlds` 使用 Node `>=22.13 <23`：

```sh
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。端口被占用则用 `npm run dev -- --port=5174`，相应打开 5174。Windows PowerShell 使用 `npm.cmd run dev`。如尚未安装依赖，先运行 `npm ci`。源码更新后刷新网页，刷新会清空会话状态。

反馈时注明设备、浏览器、检查编号及观察；截图/录屏只在难以描述或画面问题时提供即可。无需读取内部相位或数值，也无需为普通眼检打开性能工具。

M2/M4/M5 需要不同初始状态，可先完成一轮普通邀请和切换，再刷新做未邀请阻挡，最后切换系统减弱动态设置。无须每次做 10 次往返或完整 12 株测试；这些放在首次完整验收或相关行为改动后。

## 可选专项

- **M9｜发现性**：有新试玩者时，让对方仅看屏幕说明进入 Earth；记录是否能在约 30 秒内找到月亮并邀请、哪里困惑。已经熟悉路线的你无需反复模拟首次发现。
- **M10｜性能/内存**：仅在需要正式数字或发现越来越卡时执行。先确认设备和口径，再按实施计划步骤 8 的三组 60 秒帧时间采样及 heap 协议测量。用户操作 DevTools，Codex 可以离线分析你提供的导出文件/数字。没有测量就记“未量化”，不阻止日常代码工作，不宣称达到 30 FPS 或无泄漏。
