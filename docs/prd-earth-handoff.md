## 1. 接手前先理解的五件事

1. 玩家是在“成为一颗星球”，以第三人称观察整个 Earth，并非在地球表面扮演人类。当前代码名是 `space`，界面名是“星球”。本文的 Earth 指整个第四层场景，也包含月亮、其他星体和背景。
2. 游戏的主旨是自由探索、尺度变化和事物之间的关系。没有计分、胜负、强制任务、战斗或资源经营系统。
3. Earth 的主要修改文件是 [src/worlds/space.js](../src/worlds/space.js)。镜头、移动、切换、对白调度、声音和 Earth 自转目前仍由 [src/main.js](../src/main.js) 控制。
4. Earth 提供互动对象和内容；**相遇概率/频率的可配置参数属于外部共享系统，Earth 不负责实现**。保留现有 `world.talkers` 注册入口，不自行增加 Earth 专用概率开关或定时调度器。
5. 这是离线可运行的静态浏览器原型。优先完善四层短体验，不默认扩展成真实天体模拟、无限宇宙或任意实体转换系统。

接手时先读 [AGENTS.md](../AGENTS.md)、[贡献指南](../CONTRIBUTING.md)、[架构](architecture.md) 和 [验证指南](testing.md)。这些仍是仓库规则来源；本文不替代它们。

## 2. 产品定位与阶段目标

### 2.1 面向谁、解决什么体验问题

首个使用场景是黑客松演示，目标设备为支持 WebGL 2 的电脑浏览器，以单人制作、有限时间和少量协作者为前提。尚无经过试玩确认的细分用户画像或最低硬件标准。

项目受《Everything》的实体转换与跨尺度探索启发，希望验证：当玩家成为草、人、岛屿或星球时，身体、周围环境、运动节奏与事物的回应，是否让玩家产生不同的体验和好奇心。

核心表达是“人只是万物中的一种存在；换一个尺度，重要的事也会改变”。“万物存在主义”是项目的创作表述，不宣称为既有哲学学派。关于“人是近期的发明”的表达应指向认知框架，不得误写成人类物种出现年代的事实判断。

### 2.2 全项目优先顺序

| 顺序 | 目标                                   | 与 Earth 的关系                                                |
| ---- | -------------------------------------- | -------------------------------------------------------------- |
| 1    | 可公开分享、首次进入清楚、基础键鼠稳定 | 全局交付依赖；不由 Earth 独立承接托管和全局操作重写            |
| 2    | 四层画面与尺度转换更有说服力           | Earth 负责自身光影、轮廓、空间层次；跨层镜头转场由共享系统协调 |
| 3    | 增加少量可辨认的相遇内容与互动变化     | Earth 提供对象、位置、内容和约定后的局部响应                   |
| 4    | 根据反馈评估更多实体、环境、存档与手势 | 后续候选，不属于此次默认交接范围                               |

当前代码与文档没有本次确认的公网试玩链接。静态构建能力已经存在；公网发布、部署验证和素材许可确认仍是独立交付事项。

### 2.3 产品成功的观察方式

- 陌生玩家只看界面提示，就能移动、观察、切换四层，并说清自己当前成为了什么。
- 进入 Earth 后，整体轮廓、运动节奏和空间关系能让玩家感知与其他层的差异；不能仅靠标签说明。
- 建议以两三分钟短体验观察玩家是否自然发现不同对象；这不是已验证的用户数据，也不是每层必须强制触发的事件配额。
- 在选定演示电脑记录性能，建议先争取稳定 30 FPS；设备、浏览器、分辨率与测量方法需要随结果记录。当前没有正式性能预算或已测基线。
- 不通过分数、任务弹窗或密集对白强行驱动探索。

## 3. 当前游戏怎么玩

### 3.1 主循环

```text
打开页面 → 创建草场景并显示欢迎页 → 点击进入
        → 移动与观察 → 接近对象 → 偶遇短句 / 草层邀请同类
        → 随时选择另一种存在 → 继续探索
        → 返回已访问场景，延续本页会话状态
```

四层都可以直接跨级切换，无解锁条件。它们是四个独立 Three.js 场景，不是一个严格连续、按真实比例连接的宇宙。地标无需跨层一一对应，草切成岛屿后也不要求仍能找到原来的草。

### 3.2 四层现状

| 快捷键 / 索引 | 存在与显示尺度    | 已有场景与行为                                                  | 主要边界                                 |
| ------------- | ----------------- | --------------------------------------------------------------- | ---------------------------------------- |
| `1` / `0`     | 草，约 10 厘米    | 地表、草叶、露珠、花、石头；草自身摇曳，可邀请其他草跟随        | 邀请仅此层；上限 12 株                   |
| `2` / `1`     | 人，约 1.7 米     | 草原、树、岩石、远山；第三人称行走和简化肢体动画                | 无真实物理、地面碰撞避障或任务系统       |
| `3` / `2`     | 岛屿，约 1 千米   | 岛屿、树、海水着色器和远岛；岛屿缓慢移动、旋转与轻微摇晃        | 有限范围；不是海上航行模拟               |
| `4` / `3`     | 星球，约 1 万千米 | Earth、气氛层、月亮、有环星球、星点与远处尘埃；Earth 移动与自转 | X/Z 平面移动；没有轨道动力学或完整太阳系 |

显示尺度是体验文案，不能把场景坐标直接换算成真实米或千米。详细参数在第 7 节。

### 3.3 玩家可以控制什么

| 操作                     | 当前行为                                 | Earth 注意事项                             |
| ------------------------ | ---------------------------------------- | ------------------------------------------ |
| 点击“进入万物之间”       | 允许移动与切换，淡出欢迎页，尝试开启声音 | 不直接进入 Earth；默认先进入草层           |
| `W/A/S/D`，也支持方向键  | 相对镜头水平朝向移动；斜向输入会归一化   | 控制整个 Earth 的位置，不在球面行走        |
| 按住鼠标拖动             | 围绕当前实体改变镜头水平角与俯仰角       | 是环绕观察，不是点击物体触发交互           |
| 滚轮                     | 改变跟随镜头与实体的距离                 | 有共享缩放上下限；不是自由飞行镜头         |
| `1–4` 或底部按钮         | 切换存在尺度                             | `4` 进入 Earth；转场过程中忽略新的切换请求 |
| `E`                      | 草层靠近可邀请草时招募                   | Earth 中没有对应操作                       |
| 右上角声音按钮           | 开启/关闭程序合成环境声                  | 无独立 Earth 音量或配乐选择器              |
| `?`，关闭按钮或 `Escape` | 打开/关闭说明；关闭时焦点回到帮助按钮    | 说明不是完整的模拟暂停菜单                 |

没有已实现的加速、升降、跳跃、点击选中、主动对话、背包、保存、摄像头手势或手柄操作。代码会阻止空格的默认滚动，但没有空格玩法。移动端排版适配不等于已有触屏移动控制。

帮助打开时键盘移动被阻止，动画、游戏时钟和对白检测仍继续；不应承诺所有交互暂停。窗口失焦会清除按键和拖动状态。完整弹窗焦点管理仍是待办。

### 3.4 状态与切换规则

- 每层首次访问时才创建，随后缓存。同一页面内保留各层 `position`、对象和草群；刷新重置，没有跨会话存档。
- 切换会清除移动按键、隐藏当前对白和邀请提示，再淡出/切换/淡入。
- 控制器等待 480 ms 后切换场景，再等待 70 ms 移除遮罩；CSS 透明度过渡为 0.5 秒。因此不能把 550 ms 当成完整视觉转场时长。
- 每次切换都重置镜头 `zoom=1`、`yaw=0.22`；Earth 的 `pitch=0.13`。镜头角度不按场景保存。
- 切换时重置对白计时，要经过新的冷却才能出现下一句；进入 Earth 后不会立即强制对白。
- 非活动场景不执行各层的逐帧分支；Earth 离开后自转不持续推进，返回后保留已有角度。
- 场景离开时没有 GPU 资源释放流程；缓存资源直到页面结束。新增资源应复用，不能每次切换再创建一套。

## 4. Earth 的产品责任与修改边界

### 4.1 Earth 负责的体验

Earth 开发者负责第四层的视觉、物体布局、物体制作与局部互动内容。目标是让玩家看见自己作为一颗星球与其他天体的关系，感到空间的距离与存在的差异。

| 领域     | Earth 内可承担的工作                                         | 验收关注                                                          |
| -------- | ------------------------------------------------------------ | ----------------------------------------------------------------- |
| 光影     | 场景灯光、材质、球体明暗、大气边缘、约定后的云层效果         | 球体体积清楚；暗面仍可辨认；无明显闪烁或穿层                      |
| 构图     | Earth 与其他天体的位置、大小、视觉主次、背景层次             | Earth 是玩家可辨认的主体，周围对象有探索吸引力，UI 不遮挡关键视觉 |
| 建模     | Earth 表面表现、月亮、星环、其他天体的几何和材质             | 从默认距离可读，近远缩放不过度暴露原型缺陷                        |
| 新增物体 | 小量有明确体验作用的天体或空间对象                           | 说明装饰还是互动对象，是否可接近及资源成本                        |
| 互动内容 | 注册对象、空间范围、名称、原创短句；接口落地后的局部视觉响应 | 由共享系统触发；对象与对白能被玩家关联                            |

### 4.2 文件边界

| 文件/区域                                            | 此次交接边界                                                                     |

这是一份协作文件清单，不是已安装的文件写入保护或 GitHub 分支保护。扩大边界时先说明原因、受影响调用方和验收方式。无本次明确授权不提交、推送、合并或部署。

### 4.3 明确不由 Earth 实现

- 相遇概率/频率参数的定义、配置入口、取值语义、调度及随机决策。
- 全局移动、镜头和输入系统重写；四层切换与跨层尺度穿越动画。
- 其他三个世界的画面和玩法；把草群机制复制到星球层。
- 公网托管、账号、后端、遥测、付费、远程 AI 对话、多人与存档。
- 默认扩展为无限程序化宇宙、任意实体转换、真实引力、碰撞或地球表面探索。
- 摄像头手势、完整移动端支持、语音旁白及全项目音乐系统。

## 5. 当前架构与运行路径

### 5.1 技术组成

原生 HTML/CSS/JavaScript ES Modules + 本地 Three.js r170 / `0.170.0`。无前端框架、应用后端或运行时包管理器。Node.js 仅用于本地服务、检查、测试及生成静态发布目录。

```text
index.html + src/styles.css              共享 UI、遮罩、欢迎与帮助
              |
         src/main.js                    输入、状态、切换、镜头、音频、主循环
          /        \
content/worlds.js   worlds/index.js      参数表与场景工厂
                         |
                 createWorldTools(renderer)
                    shared.js           共享渲染工具与随机源
                         |
                 builders[0..3]
                /    /    /    \
           micro  human island space    四层返回独立场景状态
                                  |
                            w.talkers   由主控制器筛选并显示对白
```

`src/main.js` 创建唯一 renderer、camera 和 `requestAnimationFrame` 循环。`getWorld(index)` 延迟调用 builder 并缓存结果。`createWorldFactory(renderer)` 固定 builder 顺序为草、人、岛屿、Earth；数组索引、界面按钮和快捷键必须保持一致。

### 5.2 Earth 的实际接口

`makeSpace(tools)` 从 `src/worlds/space.js` 导出。目前同步创建并返回世界对象，没有异步资源加载协议，也没有 `update`、`interact`、`enter`、`exit` 或 `dispose` 回调。

Earth 当前使用的注入工具：

| 名称                                              | 当前契约                                                                                        |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `newWorld(index)`                                 | 创建 `THREE.Scene`、默认雾、空 `group`、位置和数组；Earth 调用 `newWorld(3)` 后覆盖背景并关闭雾 |
| `mesh(geometry, material, parent, x=0, y=0, z=0)` | 创建 Mesh、设置位置、加入 parent 并返回                                                         |
| `mat(color, extra={})`                            | 创建 `MeshStandardMaterial`，默认 `roughness=0.93`，可被 extra 覆盖                             |
| `rand(a,b)`                                       | 共享有种子的随机源，返回 `[a,b)` 区间值                                                         |

世界对象的字段及调用约束：

| 字段                        | 类型/用途                      | Earth 必须注意                                                           |
| --------------------------- | ------------------------------ | ------------------------------------------------------------------------ |
| `index`                     | 数字，Earth 为 `3`             | 不改层顺序                                                               |
| `scene`                     | `THREE.Scene`                  | renderer 渲染该对象；空间物体加入此场景                                  |
| `position`                  | `THREE.Vector3`                | 玩家位置，由主循环更新；不要用另一个位置对象脱离共享移动                 |
| `avatar`                    | `THREE.Object3D`；当前为 Group | 摄像机跟随根节点；主循环每帧覆盖其位置                                   |
| `globe`                     | `THREE.Mesh`                   | 当前 `main.js` 直接读 `w.globe.rotation.y`；不能删掉或改名而不协调调用方 |
| `talkers`                   | 互动对白记录数组               | 共享相遇系统的现有数据入口                                               |
| `followers`、`recruitables` | 草群相关数组，Earth 初始为空   | 保留公共结构，不表示 Earth 已支持招募                                    |
| `group`                     | `newWorld` 创建的空 Group      | 当前 Earth 物体没有统一挂到这里；不要误认为它是全部内容的根节点          |
| `moving`                    | `0` 或 `1`，主循环更新         | 当前是否有移动输入；不是速度向量                                         |
| `sun`                       | 当前为 DirectionalLight        | Earth 存储的灯光引用；没有 Earth 专用跟随更新逻辑                        |

### 5.3 父子关系与坐标

```text
w.scene
  ├─ w.avatar                 玩家根节点，随 w.position 移动
  │    ├─ w.globe             Earth 表面，仅这个 Mesh 由主循环自转
  │    └─ atmosphere          大气外壳，随 avatar 平移
  ├─ Moon                     当前固定世界坐标
  ├─ ringed planet group      当前固定世界坐标，包含球与星环
  ├─ stars / haze             当前固定背景点云
  └─ lights
```

跟着 Earth 平移的装饰挂在 `w.avatar` 下；独立探索对象挂在 `w.scene` 下。需要与球面同步旋转的内容要考虑是否挂在 `w.globe` 下；只挂到 `w.avatar` 不会自动随球面自转。不要直接给 `avatar.position` 加动画偏移，因为 `placeCamera()` 每帧会覆盖它。

## 6. Earth 场景当前有哪些东西

以下是源码库存，不代表最终美术要求。**Earth 之外已有月亮和有环星球两个独立天体；月亮是卫星。有环星球包含球体与星环，不应分别计成两个天体。后续月亮结伴和有环星球/土星玩法应优先复用已有对象，避免重复建模、创建副本或重复注册对白。**场景没有导入外部图片、模型、字体、音频或 CDN 资源。

| 对象       | 当前实现与数值                                                                              | 现状边界                                                    |
| ---------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |

## 8. 相遇与互动：现有接口和外部接入点

### 8.1 当前实际行为

每 12 帧调用一次 `encounter()`；在已经进入游戏且未处于切换状态时：

1. 检查距上次对白是否超过 `19` 个游戏秒。
2. 对活动世界的 `talkers` 调用 `object.getWorldPosition(...)`，用对象锚点与 `w.avatar.position` 的三维欧氏距离比较 `range`，条件是严格小于。
3. 如果有候选对象，等概率随机选一个，再随机选其一条 `lines` 显示。
4. 更新共享对白时间，正文显示约 `8.5` 个游戏秒；界面还叠加 CSS 淡入淡出。

这是“距离 + 冷却 + 候选随机选择”，不是一个已实现的可调出现概率。没有视线、屏幕可见性、物体表面距离、最近对象优先、去重、已发现记录或每对象冷却。

初次点击进入时，控制器将 `lastTalk=time-12`，因此第一句在有候选的情况下约还需 7 个游戏秒；切换尺度后设置 `lastTalk=time`，需重新超过 19 秒。`lastTalk` 是共享变量，不按对象或世界保存。

游戏时间受每帧最大 `0.05` 秒限制，低于约 20 FPS 时会比真实时间走得慢；不要按墙上时间判断对白时序。对象即使在镜头外也可能触发对白。代码只在抽样帧检测范围，极短地掠过很小范围也可能未命中。

### 8.2 Earth 保留的可用注册契约

```js
// 放在 makeSpaceScene() 内；moon 是已加入当前 scene 的 Object3D。
w.talkers.push({
  object: moon,
  range: 75,
  name: '月亮',
  lines: [['你以为你在独行。我的潮汐，却一直跟着你。', '原创 · 万物之间']],
});
```

| 字段     | 当前要求                                                 | 所属职责                                       |
| -------- | -------------------------------------------------------- | ---------------------------------------------- |
| `object` | 当前场景内有效的 `THREE.Object3D` 引用；锚点作为距离中心 | Earth 建立对象及空间位置                       |
| `range`  | 应为正的有限数字，单位同场景坐标；现有消费端没有完整校验 | Earth 提供对象的空间互动范围；需与共享策略协调 |
| `name`   | 可显示的中文名称                                         | Earth 内容                                     |
| `lines`  | 非空数组，每项为 `[正文字符串, 来源说明字符串]`          | Earth 内容；空数组会破坏现有 `say()` 的假设    |

这是当前对白接口，不等于点击、拖动物体、分支选择或触发视觉反馈的接口。不要在记录里加一个无人读取的 `onInteract` 就宣称互动已实现。

### 8.3 可配置相遇参数的对接约定

**需求 E-INT-01：**Earth 提供候选对象，外部负责人实现相遇可能性的配置和策略。当前 checkout 没有该配置字段；项目方已明确它由其他人负责。本文件不指定其名称、默认值、算法或配置界面。

对接前需要共同确定以下语义，避免两个系统重复控制频率：

| 待确认问题                                                     | 为什么需要明确                               |
| -------------------------------------------------------------- | -------------------------------------------- |
| 参数控制对象生成密度、接近后的触发概率，还是单位时间的事件率？ | 三者会产生不同的场景、随机采样和状态保留需求 |
| 在何时取样：创建场景、进入范围、冷却结束还是按游戏时间？       | 每帧直接取样会让概率依赖帧率                 |
| 作用域是全局、每层还是每种对象？                               | 决定配置归属及候选记录是否需要额外元数据     |
| 配置变更是否即时生效？如何与场景缓存配合？                     | Earth 目前只构建一次，不会因配置改变自动重建 |
| 既有 19 秒共享冷却怎样组合？重复内容如何处理？                 | 避免参数叠加后永不出现或频繁重复             |
| 自动测试怎样控制随机性？配置禁用相遇时是否仍保留装饰对象？     | 验证真实策略，避免测试偶然通过               |

在策略确定前，Earth 保持现有 `w.talkers` 数据结构和注册方式；装饰对象不必注册。不要加入未消费的 `encounterChance`、权重、空函数或假成功标记。若外部策略最终需要对象工厂、稳定 ID、类别、权重或响应回调，由双方单独确认接口和受影响调用方，再记录决策。

**验收：**Earth 无额外概率计时器；现有月亮和有环星球仍由共享系统识别；未来策略能够读取 Earth 候选。外部概率功能未接入时，交付明确标为“待对接”，不能标成 Earth 已实现或偷偷改 `range` 代替概率。

## 10. 动画、输入与资源的后续集成

### 10.1 当前无法仅靠 space.js 完成的事情

新增静态物体和对白可在 `space.js` 完成；新增月球公转、云层独立旋转、点击反馈、特殊镜头或音效切换，需要控制器入口。当前只有 Earth 表面自转被硬编码在 `main.js`，没有通用场景回调。

不要增加第二个 `requestAnimationFrame`、`setInterval` 或独立键盘监听来绕过共享主循环；它们会引入离开 Earth 后继续运行、重复注册和帧时间不一致的问题。

### 10.2 建议接口草案，尚未实现

若已选择的 Earth 功能确实需要逐帧更新，可提出以下可选方法：

```text
world.update({ dt, time, reducedMotion, moving })
```

这是提案，不可直接当作现有 API 调用。由共享控制器负责人确定调用顺序和上下文，Earth 只更新自己创建的内容。最少应约定：

- 只由主循环调用，Earth 非活动时不调用；是否在欢迎、帮助和切换期间更新要明确。
- `dt/time` 沿用现有游戏时钟，`reducedMotion` 沿用共享偏好；避免各模块自行读取不同时间。
- 迁移当前 `w.globe` 自转时，同一个 PR 明确移除旧更新路径或由共享负责人配套修改，避免双倍旋转。
- 更新顺序要保证对象最终位置可被本帧相遇检测读取；不要假定 callback 会自动收到 camera、renderer 或 DOM。
- 点击、选中、主动互动和视觉响应另需确定输入路由、坐标转换、键盘替代和反馈协议；`update` 本身不解决输入或相遇概率。

公共契约变化按仓库规则补充决策记录，确认全部 builder 调用方和测试后再落地。现在不为未来用途先放空实现。

### 10.3 生命周期与随机性

- 新 Mesh、Geometry、Material、Texture 在场景构建时创建并持有；逐帧复用对象，避免高频生成垃圾和 GPU 资源。
- 缓存场景仍会返回使用，不能在普通切换离开时 dispose 其资源。未来卸载策略需由共享生命周期统一接入。
- `tools.rand` 来自 seed=`1729` 的共享随机流，访问场景顺序和调用次数会影响之后的场景细节以及随机对白；不保证任意进入顺序都得到同一画面。
- 新增 Earth 专用随机内容建议用 `rng(seed)` 创建本地流。若迁移既有共享随机调用，还会改变后续共享流状态，必须评估并说明，不能声称迁移前后其他世界完全相同。
- 现有 planetTexture 自用 seed=`218`，其海陆纹理不依赖共享流；音频噪声另用 `Math.random()`。

## 11. 新增对象与资源时的开发方式

### 11.1 How to：添加一个沿用现有对白的对象

以下是**代码示例，不是已经加入游戏的卫星需求**。在 `makeSpaceScene()` 内、`return w` 前加入；当前文件已有 `THREE` 导入和 `mesh/mat` 工具变量：

```js
const satellite = mesh(
  new THREE.IcosahedronGeometry(2, 1),
  mat('#b7c2ce', { metalness: 0.25, roughness: 0.6 }),
  s,
  35,
  6,
  -45,
);

w.talkers.push({
  object: satellite,
  range: 30,
  name: '小小的卫星',
  lines: [['你看见的是远方，我看见的是归处。', '原创示例 · 待文案审阅']],
});
```

1. 从项目根目录运行开发服务，点击进入并按 `4`。
2. 拖动观察新物体，移动进入其范围，等待共享冷却；验证主体和对象都能辨认。
3. 返回其他层再回 Earth，确认没有重复对象；检查控制台、格式、自动检查和浏览器冒烟。

这个例子只实现静态对象和既有自动对白，不实现概率控制、点击或轨道。若看得到物体却没有对白，先检查三维锚点距离、19 个游戏秒冷却、当前活动层、是否处于转场，以及候选是否被另一个对象随机选中。

### 11.2 外部美术资源不是直接放文件就可用

当前本地静态服务只允许 `index.html` 及 `src/`、`vendor/` 下受限路径，并只提供 `.html/.js/.css/.txt` 类型；PNG、JPEG、GLB、GLTF、音频等扩展会被拒绝。当前构建也只复制 `index.html`、`src/`、`vendor/` 和第三方说明，不会复制新的顶层 `assets/`。

因此添加图片或导入模型前，要单独协调服务白名单、MIME 类型、构建复制路径和资源访问测试。Three.js 主模块之外也没有预置 GLTFLoader、后处理或其他 addons。保留运行时离线，不默认从 CDN 拉 loader 或素材。

记录资源作者、精确来源、许可、修改和随包分发方式，更新 [第三方说明](../THIRD_PARTY_NOTICES.md)。项目自身仍标为 `UNLICENSED`，不能把 Three.js 的 MIT 许可当成整个项目许可。不要把大段 base64 美术塞进源码来绕过资源流程。

## 12. 本地启动、验证与故障排查

### 12.1 How to：启动开发版

进入包含 `package.json` 的 **BetweenTheWorlds 项目根目录**，不是外层 `1017hackathon`：

```sh
# macOS/Linux，已安装 nvm 时：
cd /path/to/BetweenTheWorlds
nvm install
nvm use
npm ci
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`，进入后按 `4`。`.nvmrc` 选择 Node 22，实际要求 `>=22.13 <23`；`.npmrc` 开启 engine-strict，Node 23/24 不满足。无需 Python virtualenv、环境密钥或应用后端。nvm 未加载时，可先 `source ~/.nvm/nvm.sh`；没有安装 nvm 的机器应使用其现有版本管理方式安装符合范围的 Node。

Windows 可安装相同范围的 Node，在 PowerShell 用 `npm.cmd ci` 和 `npm.cmd run dev`，避开 `npm.ps1` 执行策略问题。Linux/Windows 详细说明见 [README](../README.md)。首次安装工具与依赖需要网络，游戏资源运行时无需外网。根目录 `index.html` 要通过 HTTP 服务打开；历史 `prototypes/offline-demo.html` 是另一份保留的单文件参考，不是开发输出。

源码保存后手动刷新，无热更新。服务仅监听 `127.0.0.1`，不能把本地地址直接发给其他电脑试玩。结束用 `Ctrl+C`。

| 症状                     | 原因与处理                                                       |
| ------------------------ | ---------------------------------------------------------------- |
| `npm ci` 报没有 lockfile | 先确认进入 `BetweenTheWorlds`，仓库已有锁文件，不要另生成一份    |
| `EBADENGINE`             | 查看 `node -v`，切换到符合范围的 Node 22                         |
| `nvm: command not found` | 检查是否安装/加载 nvm；它是 shell 函数，不是项目依赖             |
| `EADDRINUSE`             | 使用 `npm run dev -- --port=5174`，访问相应端口                  |
| 画面无法开启 WebGL       | 检查浏览器 WebGL 2 与硬件加速；代码会显示设备能力提示            |
| 新资源请求 404           | 检查服务白名单、扩展名和构建复制规则，不先归因于渲染器           |
| Earth 新增动画没动       | 当前无 `world.update` 接入；检查是否只有初始化代码，不另开主循环 |

npm run check
npx playwright install chromium
npm run test:e2e

`check` 依次运行 Prettier 检查、ESLint、Node 单元/仓库测试和静态 build；build 写入 `dist/`。`test:e2e` 对发布目录启动 `4173` 端口测试服务；`preview` 默认在 `5173` 预览 `dist/`，运行前停止占用同端口的 dev 服务。Linux 安装浏览器依赖的方式见 [验证指南](testing.md)。

5. 实现并运行规定检查，补充 Earth 场景人工验证；不要改动历史原型或第三方原件。
6. 交付可审阅 diff、同视角截图/短录屏、参数变更说明、素材许可、资源生命周期说明、真实验证结果和待对接事项。按贡献指南由另一位人类审阅后合并。
